## 0. 一句话结论

**不魔改 ALH Pro,重写一个叫 Rewind 的新应用**:借用它的架构模式与工程经验(全部来自其公开交接文档,不涉及代码复制),**三端跨平台(Win/Linux/macOS)**,核心引擎为 **Rust 核心 CLI(ffmpeg 滤镜链 + ntscrs 信号级模拟 + 自研像素层)+ Tauri 壳**,砍掉全部 AI 模型,安装包从 ~900MB 降到 **30~80MB**(含 ffmpeg),MVP 工期 1 周,完整版 6 周。

## 1. 背景与产品机会

### 1.1 需求证据

- 用户灵感来源:B 站视频《赛博文物〈金坷垃〉精修:画质太好,甚至有点不习惯了……【MiniMax H3 重绘】》(2026-09-26,3 万播放)——有人用 AI 把金坷垃重绘成高清版,评论区反而觉得"没内味"。**低清画质本身已成为一种审美内容**。
- 华强买瓜 AI 翻红报道中,观众明确表示 AI 内容"不够糙、不够怪、不够好玩",手工粗粝感才是鬼畜灵魂(澎湃新闻,thepaper.cn/newsDetail_forward_33154563)。
- B 站同时存在"4K60 华强买瓜"这类高清化玩梗内容,反向印证"低清 = 原汁原味"的社区共识。

### 1.2 市场空档

- 画质增强侧极度拥挤(Topaz、Real-ESRGAN 系、ALH Pro 等)。
- 做旧侧:中文圈只有 PR/AE 手工教程(如 B 站蒸汽波教程 BV1kA411e7EU),**无一键工具**。
- 移动端已有付费验证:Dazz 相机、ProCCD、OldRoll 等"相机即滤镜"复古 App 均为订阅制且销量可观——但它们是拍照滤镜,**不做存量视频/图片的深度做旧,更不做信号级模拟**。
- 目标用户:二创/鬼畜视频作者(B 站、抖音)、复古视觉设计师、短视频运营。

### 1.3 产品定位

> **Rewind:影像介质退化与年代质感模拟。**
> 把高清视频/图片做旧成指定年代与介质的质感——录像带、翻录光盘、CRT 显示、老胶片、监控采集、3GP 手机,以及多次转存后的电子包浆。音视频同步做旧,全部本地运行。

## 2. 关键约束:为什么不能魔改 ALH Pro

### 2.1 许可事实(已读 LICENSE 原文核实)

ALH Pro 采用**自创专有许可**(源码可见 ≠ 开源),`LICENSE` 明确:

- 允许:个人/非商用免费使用、个人学习研究。
- **禁止(未经作者 AlL.H 书面许可):复制、修改、再分发、商业用途、去除/篡改署名、反向工程后再分发。**

"魔改后自己用"已落入"修改"条款;若 Rewind 有任何分发/商业化计划(参考用户 Ametrine 背景,大概率有),则复制、再分发、商用三条全踩。

### 2.2 决策:重写,参考不复制

架构模式、工程思路、公开文档中的经验**不受版权保护**,可合法参考:

| 可合法复用(思路层) | 不可复制(代码层) |
|---|---|
| WinUI 3 + .NET 8 桌面骨架模式 | VideoService.cs / EngineService.cs 等全部源码 |
| ffmpeg 子进程调用模型(GPL 合规姿势) | XAML 视图、设置系统实现 |
| 交接文档中的工程坑清单(见 §8) | 图标、名称、文案 |
| 第三方 OSS 组件本身(ffmpeg 等,各自许可) | "ALH Pro"品牌与预设参数 |

**备选路径**:如确实想要 ALH Pro 的现成骨架代码,需先取得作者书面授权(github.com/AlLHHH/ALH-Pro / alhpro.cn)。**默认不选**——见 §2.3,重写成本低于适配成本。

### 2.3 为什么重写反而更快

ALH Pro 代码库中复杂度最高的部分,在做旧工具里**根本不存在**:

| ALH Pro 的复杂点 | 成因 | Rewind 是否需要 |
|---|---|---|
| GPU 兼容矩阵(Blackwell/老驱动/A卡降级) | AI 引擎脆弱 | 否——ffmpeg 滤镜是 CPU 确定性计算 |
| 黑帧检测 / 引擎降级链 / ncnnUnreliable | GPU 推理偶发失败 | 否 |
| ONNX/ncnn 双路线、DirectML 设备映射 | 需要 GPU 加速 | 否 |
| 200GB 临时盘管理、PNG→JPG 降盘 | AI 逐帧吃文件 | 基本否(见 §6.4,走 pipe) |
| AI 模型分发(900MB~2.4GB 安装包) | 模型体积 | 否——零模型,只需 ffmpeg |

结论:Rewind 的工程量 ≈ ALH Pro 的 30%,且没有它的脆弱面。

## 2.4 三端约束与技术栈重选(v1.1)

**新约束(2026-10-04 用户确认):必须支持 Windows / Linux / macOS。** WinUI 3 仅限 Windows,原栈作废。

### 2.4.1 决策记录

| 候选 | 优势 | 否决/当选理由 |
|---|---|---|
| **Tauri 2 + Rust 核心** | ntscrs 可直接作 crate 依赖;HTML5 `<video>` 预览零成本;安装包最小 | **当选** |
| Avalonia + .NET | 与 ALH Pro 架构同源,XAML 熟悉 | ntscrs 必须移植 Rust→C#(数周且易错);视频预览需引 LibVLC;否决 |
| Electron | 预览简单 | 像素层在 JS/WASM 尴尬;安装包 150MB+;否决 |
| Flutter | media_kit 预览不错 | Dart 像素层弱,还要 FFI 引第三门语言;否决 |
| PySide + OpenCV | 原型快 | 分发臃肿、UI 上限低、仍要移植 ntscrs;否决 |

**决定性论据**:产品的灵魂是 VHS 信号级模拟,而最好的现成实现 **ntsc-rs 的核心是独立 Rust crate `ntscrs`**(已核实 workspace 结构:`crates/ntscrs` + `gui` + `ae-plugin` + `openfx-plugin`,根目录 Apache-2.0 / MIT / ISC 三许可)。用 Rust 写核心 = 头号风险(VHS 不像)直接用 proven code 解决;其他任何语言 = 花数周移植还容易不像。

### 2.4.2 架构形态:核心 CLI 化,壳可换

```
rewind-core(Rust,库 + CLI)   ← 全部做旧逻辑、ffmpeg 编排、像素层、ntscrs
   ↑ 子进程 + JSON 参数/进度(stdio)
Tauri 壳(Web 前端)           ← 拖入/年代轴/预设/批量/对比预览
```

- **壳通过 sidecar 子进程调核心**(不是 FFI):取消 = kill 进程树(ALH Pro 同款模式),核心崩了壳不死,ffmpeg 的 GPL 编排也天然隔离在独立进程。
- 核心不依赖壳 → 未来壳可换(Avalonia/Flutter/甚至 Web 版)而不动核心;核心也可独立作为 CLI 发布(白嫖一批命令行用户)。
- 预览 = 核心以 `--preview`(限帧数/限时)跑同一参数 JSON 输出预览帧/短片段 → 前端 `<img>`/`<video>` + CSS 分割滑块对比。**预览=结果**铁律由"同一二进制同一参数"保证。

### 2.4.3 各平台工程要点

| 事项 | 方案 |
|---|---|
| ffmpeg 分发 | 每平台捆绑静态构建:Win/Linux 用 BtbN,mac 用 evermeet/osxexperts;子进程调用,GPL 合规同 ALH Pro 姿势 |
| CI 构建 | GitHub Actions 三端矩阵(windows-latest / ubuntu-latest / macos-latest),分别产 exe / AppImage+deb / dmg |
| 开发机布局 | 源码在 WSL(\\wsl.localhost\...);**cargo 不在 UNC 路径上构建**(9P 慢),Windows 工作副本 `C:\_code\rewind`。环境勘察(2026-10-04):宿主 Rust 1.96.1 MSVC + npm 华为镜像 + WebView2 就绪,**但 VS2022 未装 C++ 工作负载(link.exe 缺失,构建报 coreutils link 错)**;WSL 无免密 sudo 且缺 webkit2gtk → GUI 编译需先解除任一:①Win:`vs_installer.exe add --add Microsoft.VisualStudio.Workload.VCTools --includeRecommended`;②WSL:`sudo apt install libwebkit2gtk-4.1-dev build-essential curl wget file libxdo-dev`。Linux 核心构建已验证(WSL);mac 走 CI |
| macOS 发布 | 需要 Apple Developer 账号签名+公证($99/年),否则用户要右键打开;列入 M3 |
| Linux 发布 | Tauri 依赖系统 webkit2gtk,deb/AppImage 会处理依赖声明;老发行版需验证 |

## 3. 技术调研:做旧效果分类学 × 实现可达性

调研覆盖 20+ 中英文来源(链接见附录)。效果分 5 大类,按实现难度排序:

### 3.1 可达性矩阵

| 风格 | 灵魂特征 | ffmpeg 可达 | 需自研 | 第三方可借 |
|---|---|---|---|---|
| **2000s 低清数码**(翻录/网吧画质) | H.263/MPEG 低码率宏块、色块、蚊噪、振铃 | ✅ **强项**(低码率重编码+缩放往返+JPEG 压质) | — | Real-ESRGAN/BSRGAN 退化模型反用(BSD-3 / Apache-2.0) |
| **监控/电视购物** | 低帧率、4:1:1 色度抽稀、高增益噪、时间戳 | ✅ 全可解(fps/format/eq/drawtext) | — | — |
| **老胶片** | 颗粒、划痕、灰尘、抖动、闪烁、褪色 | 🟡 七成(noise/vignette/curves) | 随机划痕/尘埃 overlay 生成器 | MLT oldfilm 模块(参考) |
| **CRT 显示器** | 扫描线、荫罩点阵、拖影、桶形失真、色差 | 🟡 静态扫描线 | 其余全部(GLSL/C# 像素层) | crt-royale 算法(参考,许可不一) |
| **VHS 磁带** | 行级跟踪撕裂、Y/C 色度串扰、head-switching 底扭、头尾雪花 | ❌ 只能静态近似(noise+gblur+tinterlace) | **核心壁垒** | **ntsc-rs**(Apache-2.0,Rust,2600+ stars,信号级模拟,可商用) |

**结论:ffmpeg 滤镜链覆盖 60–70%;VHS 的"灵魂"(行撕裂/串扰/时变相位错误)与 CRT 显示模拟必须自研像素层,这是产品的技术壁垒,也是与"美图秀秀式滤镜"拉开差距的地方。**

## 4. 理论基础:把超分的"敌人"变成我们的武器

Real-ESRGAN(训练超分模型用的降质模型)的二阶退化管线,每一轮 = :

```
随机模糊核(高斯/广义高斯/平台核) 
→ 随机 resize(area/bilinear/bicubic,上或下采样)
→ 高斯/泊松噪声
→ JPEG 压缩
串两轮,中间插入 sinc 振铃
```

BSRGAN 进一步把退化顺序随机打乱。**这套参数空间本质就是一个"数字时代做旧采样器"**——论文作者为了让 AI 学会修复,已经把"现实世界素材是怎么变差的"研究透了。我们反着用:

- 同一套 stage,同一套参数分布,正向执行 = 做旧;
- 论文给出的参数区间直接成为我们预设的默认值(如 JPEG quality ∈ [30,95],模糊核 σ ∈ [0.2,3]);
- "翻录 N 次"玩法 = 退化管线执行 N 轮(见 §5.3)。

实现:纯数学运算(numpy 级),用 C# 自写,~500 行,无许可风险。

## 6. 做旧管线设计

### 6.1 Stage 顺序(先数字后模拟、先信号后显示,音频最后)

```
S1 色彩空间劣化   BT.601 色域、4:2:0/4:1:1 色度抽稀、白平衡漂移
S2 分辨率/锐度劣化 随机核低通 + 下采样-上采样往返
S3 数字压缩伪影   MPEG-4/H.263 低码率重编码、JPEG 宏块/蚊噪
S4 模拟信号劣化   复合串扰、行撕裂、跟踪噪声、隔行、雪花 ★自研
S5 显示端模拟     CRT 扫描线、荫罩、桶形失真、色差、晕影 ★自研(部分)
S6 介质/机械损伤   划痕、灰尘、抖动、闪烁、头尾雪花、暂停帧 ★自研生成器
S7 音频做旧       带限、底噪、wow/flutter、bitcrush、单声道(ffmpeg 全解)
```

### 6.2 各 Stage 技术实现

| Stage | ffmpeg 部分 | 自研部分 | 关键滤镜/算法 |
|---|---|---|---|
| S1 | ✅(M3 补全) | — | `chroma_decimate`(format=yuv411p→yuv420p 往返,消费级 VHS/监控 4:1:1)、`matrix_roundtrip`(colormatrix 709→601→709 复合解码色偏)、白平衡漂移(color.green_mid/blue_mid)。证据 .work/samples/sheet_s1.png:4:1:1 开启后运动彩条色度细节横向变糙而亮度边缘仍锐 |
| S2 | ✅ | — | `gblur`/`boxblur` + `scale=w:h:flags=neighbor|bicubic` 往返 |
| S3 | ✅ | — | `-c:v mpeg4 -b:v 200k` 重编码;图片走 `-q:v 31` mjpeg |
| S4 | ❌(仅静态近似) | **行撕裂、Y/C 串扰、跟踪噪声带、head-switching、时变雪花** | 参考 ntsc-rs 算法:Y/C 分离→色度相位噪声→行位移场→再合成 |
| S5 | 🟡(静态扫描线) | **荫罩点阵、桶形失真、色差、拖影** | 扫描线可用 `curves`+周期图案 overlay;其余 C# 像素层 |
| S6 | 🟡 | **划痕/尘埃 overlay 程序生成器、抖动/闪烁调制** | 噪声场+形态学生成划痕;`crop`+`pad` 正弦抖动;`eq=brightness` LFO |
| S7 | ✅ | — | 见 §3.3 |

### 6.3 执行策略:一条链还是拆帧?

| 策略 | 适用 | 优点 | 缺点 |
|---|---|---|---|
| **A. ffmpeg 单条 filter_complex** | 预设只含 S1–S3 + 轻量 S5/S6 近似 | 零中间文件、最快 | 表达力受滤镜语言限制 |
| **B. rawvideo pipe + C# 帧处理** | 含 S4/S5/S6 自研效果 | 表达力无限、无磁盘 IO | 需自写管线 |
| C. 拆帧到临时目录(ALH Pro 姿势) | — | 简单 | 磁盘 IO 大,无必要 |

**决策:双引擎**。
- **FastPath(策略 A)**:预设效果可全部由 ffmpeg 表达时,单进程一把梭,进度解析 ffmpeg stdout。
- **PixelPath(策略 B)**:含自研 stage 时,ffmpeg 解码 → stdout pipe rawvideo → Rust 帧处理器(PixelOp 序列,ntscrs/自研)→ stdin pipe 回 ffmpeg 编码。同一进程图,无临时文件。
- 预设 stage 名称即路由依据(asymmetric_lowpass/interlace_comb 等走 ffmpeg;ntsc_vhs/crt_display/film_damage 走 pixel)。
- **M2-c 起为统一 Step 序列**:`Plan{steps:[Step::Fast(Pass)|Step::Pixel(Seg)]}`,像素段可被 ffmpeg 趟/codec 趟分隔多段,段画布在段首快照;pipeline 顺序执行并管理临时链。

### 6.4 与 ALH Pro 的模式映射(参考关系,非代码关系)

| Rewind 模块 | 参考 ALH Pro 的什么模式 | 关键区别 |
|---|---|---|
| FfmpegService(进程封装/进度解析/取消) | EngineService 的 exe 子进程模型 | 只有 ffmpeg 一个引擎,无 GPU 探测、无降级链 |
| PipelineBuilder(stage→filter 串) | AlhPro.Core.VideoPostFilters 滤镜串构造 | 我们的滤镜方向相反(降质) |
| PresetService(JSON+版本迁移) | video-presets.json 预设机制 | 新增年代轴联动参数 |
| 批量队列/进度回调 | IProgress<(pct,msg)> + CancellationToken | 照搬模式 |
| 临时空间预检 | TempSpaceEstimate | 简化(pipe 模式只需输出空间) |
| 编码器选择 | nvenc>amf>qsv>libx264 降级 | 照搬模式(v1 可只做 libx264+nvenc) |
| 打包 | Inno Setup 三变体 | 只需一个变体(~80MB) |

## 8. 工程坑清单(继承自 ALH Pro 公开交接文档)

这些是 ALH Pro 用真实用户事故换来的经验,重写时直接内置:

1. **中文路径**:ffmpeg 在 GBK 系统遇中文路径报 "Illegal byte sequence" → 输入一律先转 8.3 短路径(或 pipe 化后此问题消失,但文件路径仍需)。**2026-10-04 注**:Rust `Command` 在 Windows 经 CreateProcessW 传 UTF-16 参数,现代 BtbN 构建理论上无 GBK 问题;8.3 短路径作为历史保险暂不实现,**Windows 环境就绪后第一件事就是拿中文/emoji 路径实测,再决定去留**(不写无法验证的 FFI)。
2. **输出原子性**:先写 `xxx.tmp` 再改名,防中断留半成品(进度显示 100% 但文件损坏)。
3. **VFR 源**:手机录屏是变帧率,直接处理会音画错位 → ffprobe 先探测,必要时先转 CFR。
4. **HDR 源**:iPhone HDR 视频直接处理会变色 → 探测到 BT.2020 先转 BT.709 SDR 再做旧(做旧不需要 HDR 保真)。
5. **进程取消**:`p.Kill(entireProcessTree: true)`,否则 ffmpeg 子进程残留吃 CPU。
6. **设置污染**:构造函数/加载期控件 `SelectedIndex=-1` 会写脏设置文件 → 加 `_settingsLoaded` 守卫。
7. **预览=结果**:预览与出片必须同一条管线同一参数,不许两套检测器。
8. **打包**:Inno Setup;GitHub 单资产上限 2GB(我们 ~80MB 无此问题);上传资产用 `--data-binary` 不用 multipart。

### 8.1 M0 实测新增(2026-10-04,ffmpeg 4.4.2 验证)

9. **drawtext 字面冒号转义不可靠**:`%H\:%M\:%S`、`%H\\:%M\\:%S` 两种转义都会触发 `%{localtime} requires at most 1 arguments`;**正确解法是换无冒号格式符 `%T`**(等价 %H:%M:%S)。
10. **vignette 滤镜是"窥镜"不是"暗角"**:angle 从 PI/4.5 到 PI/8 都是硬边圆形遮罩,观感像望远镜;VHS 介质本无镜头暗角 → VHS 预设移除 vignette,胶片预设如需要须自研柔和径向衰减。
11. **压缩伪影定标必须用细节丰富的片源**:testsrc2 的平色块在任何码率下都"压不坏",会严重低估劣化强度;mandelbrot(分形纹理)才能把宏块/蚊噪逼出来。定标双片源已成脚本标配(m0_probe_v2.sh)。
12. **真编码器是最佳伪影生成器**:H.263(QCIF 176x144,仅支持固定分辨率)、mpeg4-part2(q14+)、mjpeg 的真宏块/蚊噪远胜任何噪声滤镜模拟——S3 不做"模拟压缩",做"真压缩往返"。
13. **音频做旧三件套已验证**:`aresample=8000` 往返 + `acrusher` bitcrush(电话/手机感)、`anoisesrc` 粉噪 amix(磁带底噪)、带限 highpass/lowpass,全部 ffmpeg 4.4 原生。
14. **`tinterlace=mode=merge` 会把帧高翻倍**(480→960,每场还原为半高再织入):必须后接 `scale` 缩回原高——缩放恰好把梳齿烘进原生高度。漏掉这步输出会变 720x960 竖拉伸。
15. **ntscrs spike 通过(2026-10-04)**:vendor 路径依赖 + `apply_effect_to_buffer::<Rgb,u8>` 就地处理,`SettingsBlock{enabled:true,settings:VHSSettings::default()}` 显式开 VHS(`SettingsBlock::enabled()` 是 pub(crate),字段是 pub);720x480 单帧 **8.3ms**(release+rayon,≈120fps,实时级)。`SettingsBlock::from(Some(T))` 亦是公开构造路径。与 ffmpeg 静态近似同框对比见 .work/samples/sheet_spike.png——近似版只是"糊",ntscrs 有梳齿/色度振铃/底部磁头切换噪声,是"录像带"。
16. **M1a 引擎实测(2026-10-04)**:FastPath 多趟 + PixelPath 双管线全通(5 预设视频 + 图片 + 预览 + 批量,单测 6/6)。两个踩过的坑:①多趟管线清理临时文件时必须跳过用户输入(`i>0` 才删 prev,曾把输入当临时文件删掉);②PixelPath 预览要在**编码命令加输出级 `-t`**——解码侧限长不管 mux 进来的全片长音频,输出会被拖回原时长。
17. **H.263 只吃固定分辨率**(176x144/352x288 等):年代轴 2013 锚点配 480x360 直接编码失败。解法:codec_roundtrip 增加 `bitrate` 模式(libx264 -b:v 250k = 真"360P 网页时代")。约束:q 模式与 bitrate 模式二选一。
18. **定标值不要写进断言**:测试对预设具体强度值(barrel=0.45)做等值断言,定标一调就红——改为区间断言(0.05<s<1.0),锁结构不锁数值。
19. **性能剖析(2026-10-04,WSL2 CPU,10s 1080p30 全片):** 瓶颈不在像素算法而在**中间趟 x264 默认 preset 编码**。改中间趟/像素趟为 `-preset ultrafast -crf 14`(终趟仍 crf20)后:

    | 预设 | 优化前 | 优化后 | 有效速度 |
    |---|---|---|---|
    | dvd2005(FastPath×2) | 13.1s | **8.5s** | 1.2×RT |
    | era_1990(混排+ntscrs) | 45.1s | **33.0s** | 0.3×RT |
    | crt1995(像素段 rayon 并行) | 21.1s | **8.2s** | 1.2×RT |
    | film1970(1080p 像素损伤) | 99.3s | **23.9s** | 0.42×RT |

    附带教训:带宽型单遍乘法(flicker)上 rayon 反而变慢——分片开销>收益;rayon 只用于逐行重计算(CRT 三 pass)。
20. **像素管线浸泡(2026-10-04)**:20 文件 × vhs1990_ntscrs(PixelPath)批量 27.4s、峰值 RSS 460MB、临时文件零残留(管线清理逻辑含 i>0 输入保护 + 每步失败即删半成品)。**Windows 本机工具链判定:无 mingw/zig,VS2022 缺 C++ 负载 → 本机 Windows 编译只能靠装 C++ 工作负载或 CI 矩阵(已配),不再找绕行方案。**

24. **M4 首批(P0-a/b/c)实测坑(2026-10-04)**:
    ① **像素路径根本不理 fps stage**:`pixel.rs` 取的是 `media.fps`,年代轴写的 `fps` 只对 FastPath 生效——1990 那种 ntscrs 预设改帧率毫无反应。修法是把生效帧率**快照进 PixelSeg**,在解码链最前面 `fps=X:round=down`,并把编码侧 `-r` 换成该值。
    ② **`tmix` 的 weights 空格不能用双引号**:我们的滤镜串是直接进 argv 的,`weights="0.5 1"` 报 `Invalid syntax for weights[0]`;**单引号 `weights='0.5 1'` 或反斜杠转义空格**才行(同 §8.1-9 的转义家族)。
    ③ **非方像素交付会静默拉扁画面**:SD 段设了 SAR 10:11,末段 `scale` 回 HD 时若不先去挤压,活动区量到的是 **1080×720(1.500)**——人变瘦;先在交付段前插 `scale='trunc(iw*10/11/2)*2':ih,setsar=1`,活动区变成 **982×720(1.361)** 才是真实显示画幅。这条是 `axis_check.sh` 用 cropdetect 机读的。
    ④ **`out_range=full` 只改像素不改标签**:最终趟必须补 `-color_range pc`,否则 ffprobe 报 `color_range=unknown`,播放器再压一遍黑场。
    ⑤ **serde 会静默丢掉不存在的参数名**:`--override fps.sped=6` 不报错也不生效。所以覆盖在写入前先拿 `describe` 清单校验参数名,拼错直接报错并回列可用参数。
    ⑥ **覆盖一个预设里没有的 stage 要按管线位次插入**:界面的一级"帧率"对任何预设都要生效;`fps` rank=20 而 `noise`=70,插错位置会改变语义。插入还必须带清单默认值(否则 `Fps` 缺 `fps` 字段反序列化失败)。
    ⑦ **`round=down` 与 `near` 在"只丢不补"的换算下帧数与 YDIF 几乎相同**(实测 30→25:150/150 帧,YDIF 4.280 vs 4.284):差别只在目标帧率高于源或源为 VFR 时才显现,所以 `round` 用单测锁语法,e2e 不拿它当断言(避免假指标)。
    实测口径(1280×720@30 的 mandelbrot 6s 备测源,`scripts/axis_check.sh`):30fps→180 帧 YDIF 3.90;25→150 帧 4.28;**12.5→75 帧 5.11(像素路径,证明 ① 已修)**;12.5+快门 1.0→73 帧 3.79(模糊压住抖动,且 tmix 会吃掉尾帧 2 帧);FastPath cctv2000@15→90 帧。测试规模 **core 42/42、shell 9/9、regression 29/29、axis check 全绿**;UI 侧 `describe` 发布 59 个可调参数(15 项进一级控件、44 项进专家面板,一个参数只渲染一次),浏览器实测把帧率从预设的 15 覆盖成 6 → 成品 `avg_frame_rate=6/1`、`nb_frames=36`,重载后覆盖与读数仍恢复,控制台零消息。
25. **M5a 界面重排暴露的引擎与安全坑(2026-10-04)**:①**静帧走时序 stage 会输出 0 帧** —— `tinterlace=merge` 吃两帧出一帧,单帧输入直接空输出,`fps`/`tape_ends` 的时间窗对图片也无意义;现在 `build_plan` 在 `media.is_image()` 时剥掉这三类 stage(回归闸图片模式已扩到全部 7 个预设,正是它抓出来的)。②**ffmpeg 退出码 0 ≠ 有产物**:上面那次空输出照样 exit 0,错误漂到后面变成莫名的"改名输出失败";`run_pass` 现在校验目标存在且非空,并把 ffmpeg 尾部输出带进报错。③**画廊瓦片不能缩放**:720×480 缩到 480×270 会把扫描线与宏块平均掉,对比图等于没做;改为按成品画布 **1:1 中心取块**,小画布(3GP 176×144)用 `neighbor` 整数放大。④**`/file` 是任意文件读取洞**:原来任何绝对路径都能读、响应还带 `Access-Control-Allow-Origin: *`,本机任意网页即可借 127.0.0.1 服务读盘;现在去 CORS 头 + 白名单(只放行本服务登记过的上传件/成品/预览帧),实测未登记路径 403。⑤示例素材要复制进上传目录再用,否则默认输出目录落在仓库里(实测污染过 `fixtures/`)。

31. **奇数边长与静帧时间轴:两个"输入形状"缺陷(用户拿 reference.png 实测报回)**:① `2560×1439` 的图在 **step1/3 的 libx264** 上炸 `height not divisible by 2` —— yuv420 系编码器(mpeg4 / H.263 / libx264)要求偶数边长,而 `build_plan` 从没把画布取偶,任何奇数素材(截屏录像、裁过的图)都进不来。现在 `ffgraph::even_dim()` 向下取偶(绝不放大),并由**计划第 0 步**负责兑现:Fast 趟在链头 prepend `scale=w:h:flags=area`,像素段用取偶后的 seg 尺寸(解码链自带 `scale`),用户填的奇数 `resize.w/h` 目标同样取偶。② 图片预览返回**成功却没有文件**:`-ss 1` 对静帧抽出 0 帧而 ffmpeg 照样 exit 0,`extract_frame` 只看退出码;而 UI 的 `t = Math.min(1.0, (duration||2)/2)` 对 `duration=0` 恰好算出 **1.0**,所以每次图片预览都在取用两个不存在的路径。现在图片的时间一律按 0(`pipeline::preview` 先 probe 判 `is_image`),且 `extract_frame` 校验产物存在且非空。

32. **做旧系数与"平均色看不见纹理"(M6 两条)**:① 阶梯必须**同时改尺寸**才有效 —— 实测同尺寸同 q 反复往返会收敛(8 代后 72950 B ≈ 单代 72956 B),所以"多来几手"如果不降采样就是在原地打转;这也是 `MAX_AGING=8` 的依据,而不是拍脑袋的上限。展开点选在 `build_plan` 里而不是预先把 stage 列表复制 N 份:阶梯尺寸要按**预设走完后的真实画幅**算,而 `fit:"inside"` 是"盒"(只降不升),盒尺寸 ≠ 真实尺寸 —— 早先按盒算会把 320×240 的素材放大成 664×372(实测抓到,已进单测)。② 差异度闸最初用整帧缩略的 YUV 均值,结果 `crt1995` 与 `vhs1990_static` 最大差只有 1.67、`dvd2005` 与 `phone2010` 只有 3.57 —— 64×64 缩略把扫描线与宏块**平均掉了**,平均色这个代理指标根本看不见纹理。换成"色距 / 高频能量(1:1 右半拉普拉斯标准差)/ 8px 周期块度"三信号取或,阈值从 12 预设 65 对的实测分布里取(最小综合距离 1.48 → 判据 1.0)。**教训:先验证度量本身能不能分辨已知不同的东西,再拿它去断言相同。** ③ 顺带两条环境坑:`requestAnimationFrame` 在零尺寸/后台表面里**不触发**,用它加 `.show` 类会让界面自动化断言永远看不到弹层出现 —— 改 `setTimeout(…,16)`;而 `display:none` 下 `scrollWidth`/`clientWidth` 都是 0,拿它断言"标签没截断"是**空断言**,必须先确认容器真的可见再量。


33. **"电子包浆"不等于"画面要发绿"(用户截图报回,两条)**:① `band_quantize` 最初把 `trunc(val/L)*L+L/3` 同时套在 y/u/v 上 —— L=20 意味着**色度只剩约 6 级**,整帧均值实测被推 U−6.4/V−7.4,看起来就是一层发绿的斑块而不是色带。改成**默认只砍亮度**(`chroma: false`,要连色度一起砍得显式打开),同一张图降到 U−1.3/V−1.8。② 偏色从"阶梯到第 3 手自动加"改成**显式可选参数** `preset.cast`(0–1,默认 0),界面一级滑块「偏色 · 变绿」默认显示"关"。理由就是用户那句话:变绿是"贴吧/QQ 那一路"的味道,不是包浆的定义。
    **度量踩坑(比缺陷本身更值得记)**:我最初用**整帧平均色度**去验证 cast,读数只有 0.2 个单位,一度得出"符号反了、旋钮是装饰"的结论 —— 错在量具:参考图大面积是平涂黄底,肤色那点偏移被稀释掉了。真正的证据是①同一张图 cast 0→1 的**成品体积**从 372 KB 涨到 431 KB(色度熵在动),②把 5 代阶梯的偏移累加起来测:ΔU **0 / −7.6 / −14.4 / −19.0**、ΔV 0 / −2.9 / −7.7 / −12.8(cast 0/0.3/0.6/1.0,单调且量级足够)。另外那次隔离实验自己还犯了个低级错:`-vf` 传了两次,后一个把前一个整个覆盖掉,于是"colorbalance 完全无效"——**探针本身要先证明它没骗人**(同 §8.1-30 的红绿验证一个道理)。对照图 `.work/samples/sheet_cast.png`(该目录 gitignore,本地证据图)。单测 `band_quantize_is_luma_only_by_default` 与 `cast_defaults_to_no_hue_shift_and_only_tints_when_asked` 钉住两件事:默认链里不含 `:u=`/`:v=`;默认不含任何 `colorbalance`,开了才逐代加 `gm=0.11…0.5`。

34. **共享临时文件名:并发不是"批量才有的事",默认动作里就带着它**:验 D10 时抽帧报 `step5/5 趟没有产出文件(滤镜链吃掉了全部帧?)`。查下去发现跟滤镜链无关 —— 预览与抽帧并发跑**同一素材**,而 `.{stem}_{preset}.tmp.mp4` 和逐趟中间文件 `.{stem}_{preset}.s{i}.tmp.ext` 都不含运行身份,两路互相删对方的中间产物;成品名又是"跑之前先看存不存在"选的,两路会选中同一个 `{base}.mp4`,后写的盖掉前写的、被前写的删掉。之所以一直没暴露:**上传后自动预览 + 同时抽 6 帧就是默认路径**,必现;而此前所有闸都是"一条命令跑一件事"。修法:每次运行一个 `run_tag()`(pid + 毫秒 + 进程内 `AtomicU64`)进所有临时名;成品名改到跑完时用 `create_new`(O_EXCL)占位,同名自动 `-1/-2`,rename 失败即回收占位 —— 顺带把"永不静默覆盖"从 TOCTOU 变成真原子。**新闸 `scripts/conc_check.sh`(6 项,自起服务、自造 4 分钟素材,31 s)**;红绿双向验过:把 `run_tag()` 钉成常量 → "并发两趟 run 只剩 1 个成品" 判红,验完撤钩子(不给源码留测试专用分支)。**同类隐患:凡是"先探测存在再写入"的命名都要改成 O_EXCL 占位;凡是并发会共享的名字都要带运行身份。**
35. **门槛自己把自己拆了两次(实现 D12 时)**:① `renderSamples` 结尾写了"抽到帧就算看过了"(`if (pairs.length && needsConfirm(it)) state.confirmed = true`),而抽帧是**自动**发生的 —— 于是 300 s 素材传完按钮直接是亮的,门槛等于装饰。② `probeItem` 是异步的,而门槛只在 `setFocus` 里算一次:那一刻 `it.probe` 还是 null,`needsConfirm` 读不到时长就返回 false,probe 回来后没人重算 —— 用户担心的"传完就开跑"恰好发生在 probe 的空窗里。修法:确认必须是**用户动作**(点某帧 = 顺带把预览锚点定过去;或按「看过了,可以开跑」,抽帧失败时这条仍在,不会死锁);probe 落地后重算 `refreshSamples + refreshGate`。**教训:加保护时立刻写一条"试图绕过它"的断言并跑一遍**(此处是"上传 300 s 素材后 12 s 内 start 必须仍然 disabled"),否则保护常常只存在于文案里。同批顺手修的两处焦点问题:更换素材后焦点跳到相邻旧素材(现在落到新来的那份,门槛随即重新武装)、移除全部素材后「再翻录一次」仍亮着(它此前跟着 `state.lastOutput`,现在跟着"眼前这一项有没有成品",删干净就是灰的)。
36. **画廊的可见性判断散在界面里,于是"换一批"能把一张卡弄丢**:界面用 `kind !== 'derived'` 决定哪些预设进画廊,而 `reroll` 会把内置预设写成 `derived/<同 id>.json` —— 点一次「换一批」,那张卡就从画廊消失,预设却还在用、也再也选不回来。同一条链上还有第二个洞:年代轴/换一批之后界面重拉 `app_info`,那两处是裸赋值 `state.presets = info.presets`,绕过了"把变体展开成可选预设"这一步,于是新加的「类型」行凭空消失。**教训:凡是"哪些东西可见"的判断都得有个唯一出处。** 现在引擎在 catalog 里给每条记录一个 `card` 布尔(只有年代轴产物 `card:false`;变体折进基准卡片的 `variants` 时也标 `card:false`),界面只认 `p.card`,目录读取统一走 `applyCatalog()`;`catalog::tests` 与 `release_check` 各钉一条,红绿都验过(去掉 fold → "类型变体在 catalog 里可见" 判红)。
37. **`cargo test --release` 不会刷新独立二进制,于是"已修好"的界面还在跑旧逻辑**:改完 `card` 标记后只跑了 `cargo test --release`(54 项全过),重启服务、开浏览器 → 画廊仍是 11 张卡。查下来是 `target/release/rewind-core` 这个 bin 产物没被 test 构建刷新,服务跑的是旧镜像。**验证行为必须显式 `cargo build --release` 再重启服务**,否则测的是旧代码;这条已经坑过两次(前一次是 debug/release 双产物)。
38. **绝对定位的画布会把正常流的兄弟节点盖住**:`#samples` 与 `.viewer` 同在 `.canvas` 里,`.viewer{position:absolute;inset:0}` 于是把抽帧条整个盖在下面 —— 用户看到的不是"布局丑",而是**抽帧图浮在主画面上**。修法是加一层 `.stage-main`(relative,flex:1)只包住"该叠起来的三态",抽帧条留在它下面。断言用几何:`samples.top == stage-main.bottom` 且主画面高度没被吃掉(实测 755px)。
39. **同一份设置两种存法,新字段会被桌面版静默吞掉**:Web 版 `serve::set_settings` 把前端给的 JSON 原样落盘,桌面版 `app::set_settings` 却先 `serde_json::from_value::<AppSettings>()` 再序列化 —— 于是界面新加的 `lang` 在桌面版"存了但没存",表现为换语言后重启又变回去,而且**两端都不报错**。补字段 + `assert_eq!(load().lang.as_deref(), Some("en"))`。编译器当场抓到(`missing field lang in initializer`),前提是结构体没有 `#[serde(default)]` 之外的兜底 —— 这条要记的是:**跨形态共用的持久化,字段清单只能有一份;两端各写一遍读写路径,新字段必然漏一侧。**
40. **i18n 不要往引擎里塞 `label_en`**:59 个参数 × 2 种语言的直觉做法是引擎发双语,代价是引擎的中文 label 与英文 label 会各自漂移,而且预设文件、年代轴、错误消息都得跟着改。现在的分工:**中文以引擎为源,英文按机器 id 在界面侧查表**(`resize.w` / `crt_display` / `geometry` / `patina`),覆盖率由 `scripts/i18n_check.js` 钉死 —— 新增参数忘翻译不是"界面显示中文",而是**闸直接红**。代价是术语表与引擎分处两地,所以断言必须从 `rewind-core describe` 的实时输出取键,而不是抄一份清单。
41. **重渲染要覆盖"不走清单渲染那条路"的读数**:第一次切英文,标题、菜单、预设名、参数标签全变了,唯独 `2 手` / `关` 没变 —— 它们由 `setAging`/`setCast` 写,不在 `refreshReadouts()` 的范围内;补完又发现派生预设 chip 也没重渲染。**语言切换本质是一次全量重绘,漏一个控件就是一个死角**;加 `renderGauges()`/`renderRecipeChip()` 进 `setLang`,并在浏览器里断言 `I18N.missing === []`(键没兜空)。
42. **"试试示例素材"给的是纯色块 —— 一次素材选择失误,加一条可量的判据**:内置示例一直是 `fixtures/test_src.mp4`(ffmpeg `testsrc2`:色条 + 滚动计数器),定标样片 `src_hd.mp4` 也是 SMPTE 色条、`src_mand.mp4` 是曼德博。做旧效果在色块上**几乎全都看不出来**:没有皮肤、没有发丝、没有文字边缘、没有自然渐变,压缩噪声无处显形。用户一句话点破。修法是给仓库生成一张**原创照片级**素材(有脸、有织物、有天空渐变、有细电线、有蒸汽),再配一条能分辨"照片 vs 测试图"的断言:取一帧缩到 128×72,量"极端饱和像素占比"与"纯原色占比" —— 实测 `testsrc2` **86.2% / 6.7%**、照片 **0.0% / 0.0%**,阈值 25% / 3%。**第一版量具用"颜色种数",结果测试图也有 741 种、照片 1864 种,差得不够远 —— 又一次"先验量具能不能分辨已知不同的东西"**(同 §8.1-32②)。素材本身要可分发:AI 生成 + 随仓库 MIT,别把第三方影视截图打进包里。
43. **示例素材的解析规则在 Web 与桌面各写了一份,换素材时只改对了一半**:`serve.rs` 的 `sample_file` 分支和 `shell::sample_file()` 各自列了一遍候选路径。我把 shell 那份换成新素材后,界面还在拿旧色块 —— **没有任何报错,只是效果不对**。现在规则收进 `core::assets`(含 `REWIND_SAMPLE` 覆盖与 `.part`+rename 的原子复制),壳改走 `rewind-core sample --out-dir …`。**判据:同一件事在两个 crate 里各写一遍,就一定会出现两个答案** —— 这条和 §8.1-36(画廊可见性)、§8.1-39(设置字段)是同一个病的三次发作。
44. **"词典改了、元素没接上"是覆盖率闸查不到的死角**:`配方`→`预设` 的术语清扫里,我把 `clear.overrides` 的词典值改成「清除全部自定义」,但 `#clear-overrides` 是 index.html 里的静态标签、根本没挂 `data-i18n` —— 词典键集一致、用到的 key 都存在、app.js 无硬编码中文,三条全绿,界面上还是旧词。**这三条量的是"词典与代码的关系",量不到"HTML 与词典的关系"**。补的闸是把 HTML 解析成开标签栈:带中文的正文必须落在一个有 `data-i18n` 的元素里,带中文的 `title/aria-label/alt` 必须有对应的 `data-i18n-*`;`int-label`/`cast-label`/`era-year` 这类 JS 会重写的读数进显式白名单(否则闸会误伤)。**变红验证做两次**:删掉按钮的 `data-i18n`、删掉 `#strip` 的 `data-i18n-aria`,两条各自红,再逐字节 `cmp` 还原。
45. **批量替换表能一键把中文写进英文词典**:同一次清扫用一张 100 条的 `(旧串, 新串)` 表改 i18n.js,表里 `'(recipe {p})' → '(预设 {p})'` 不分中英,于是 en 块的 `run.preset` 变成了中文 —— 键集仍然一致,所以原有闸全都不叫。新增一条 `en 词典不许混入中文值`,白名单只留 `lang.switch`(语言开关要用对方语言的自称:英文界面上那个按钮就该写「中文」)。**教训:批量替换的粒度必须能区分"同一段的两个副本",否则它一定比你想改的范围更大**(同 §8.1-38 那次全仓 `sed -i` 喂进了二进制文件)。
46. **"预览即成品"漏了另一半:成品的画幅也变了**:用户用「监控录像」时看到"输出比原画面小一圈、两层叠在一起"。根因是对比预览的两张图各来自两处 —— 原帧是**素材原生尺寸**,成品帧是**预设交付尺寸**,两层各自 `object-fit: contain` 到同一个盒子,于是不同宽、滑杆扫过去像两张画。实测 11 个内置预设里 3 个会改画幅(`cctv2000` 640×480、`vhs1990_static` 720×480、`rmvb2006` 1280×720 带 DAR 4:3)。**修在引擎而不是 CSS**:计划新增 `Plan::geom`(预设自己的缩放/裁切/补边/像素比),原帧抽出来时套同一条链,再按 `display_dims()` 折算成呈现尺寸,两层像素级同几何。两个刻意的边界:① 做旧阶梯是"降到画幅×0.72ⁿ 再拉回画幅"的恒等段,**不进 geom**,否则"原片"那一层白挨 N 次重采样、差异被量小;② 净几何恒等时干脆一个滤镜都不套,实测 8/11 个预设的原帧与裸抽帧 md5 一字不差。图片另有一层:PNG 的 SAR 只有 ffmpeg 认,浏览器按方像素画,所以静帧末趟把 DAR 烘进像素(`scale` + `setsar=1`,实测 1792×1024+SAR 16:21 → 1364×1024 无 SAR),视频仍走元数据。**还有一条产品判断:画幅变了要在界面上说出来**(预览工具条「输出 1280×720 · 画幅 4:3」,恒等时不占位),外加把三处静图缩略位从 `cover` 改 `contain` —— cover 会裁掉非 16:9 的画面,用户挑帧时看到的本来就是切过的。
47. **条件断言的"前置条件"也要自检,否则它就是一条恒绿的假闸**:`geo_check.sh` 第 3 条(净几何恒等 → 原帧不许被重采样)写成 `if 交付尺寸 == 源尺寸 && 无 DAR && 无裁切`,而源尺寸是从 `ffprobe csv` 直接拿的 `1280,720`,比较用的是 `${SW#*x}` —— 逗号永远切不出 720,条件恒假。第一次变红试验(把 `reframes` 钉成 `true`)跑完是 **PASS=36 FAIL=0**:注入明明生效了、闸却不动,才回头量到量具本身是空的。补法不是把条件写巧一点,而是**让分支自己报数**:`PRISTINE_SEEN >= 5` 不成立就判红,并在开头断言 `SW` 解析成了 `WxH` 形状。**判据:凡是"只在某些情况下才检查"的断言,都要有一条"这些情况确实出现过"的计数**;这和 §8.1-32②、§8.1-42 是同一件事 —— 先量量具能不能分辨已知不同的东西,再拿它当闸。
48. **"缓存非空就不重算"是跨对象脏状态的母形态**:用户报"图片也会抽帧",而实测发现抽帧栏比这更糟 —— `refreshSamples` 的重抽条件是 `if (!els.samplesStrip.childElementCount) requestSamples()`,切换素材却从不清空,于是聚焦到第二项时条里挂的还是第一项的 `0:01…0:07` 六格,并且**新素材永远不再抽**。同一次修复里还有第二条:静帧不该进"抽帧确认",而 `needsConfirm` 的尺寸分支(>200 MB 要确认)对图片照样生效,偏偏解除确认的按钮在被隐藏的抽帧栏里 —— **门槛成了死锁**。修法是给集合型 UI 状态一个**归属键**(`samplesKey = 路径|种子`),归属不符即清空重算,失败也清键(否则永远停在"加载中");键刻意不含参数,因为抽帧回答的是"这条素材长什么样",参数进键等于每拖一次滑杆重跑 6 趟 ffmpeg。**判据:凡是"渲染进一个共享 DOM 容器 + 用容器空不空当'还没算'"的地方,都要问一句"这个容器现在属于谁"** —— 与 §8.1-41(切语言漏控件)、§8.1-44(改了词典没接元素)同族:状态存在哪儿,谁负责作废它。
49. **一次"扫同类错误"的账目:21 报 → 15 修 → 4 证伪 → 2 留档,以及"手写第二份重置清单"这个母形态**。用户要求把低级逻辑错误扫干净,做法是两路只读并行审计(界面 / 引擎)+ **每条自己复现**后才动手。三条可复用的判据:① **重复一份"重置/清理/构造"清单就是缺陷源**:`removeItem` 手抄了 `setFocus` 的 8 行重置,漏了抽帧面板与 `confirmed`,后果是"门槛永久隐藏、无法自救"和"删掉 A 之后 B 静默过门槛"。修法不是补两行,而是让 `removeItem` 委托 `setFocus` —— 只留一份清单。同理 `probe` 与 `inspect` 各写一遍时长取法,两边答案不同。② **"看起来没事"不等于"没在白干活"**:无音轨素材的 `-map ""` 没让成品出错(最终趟早有 `has_audio` 门),但**每一趟中间编码都在多塞一条完整原片视频轨**,实测 84533 B vs 19407 B(4.4×)。只看最终产物的断言看不见这种账。③ **审计结论必须逐条量,包括看起来显然的**:4 条被证伪 —— 截断 mp4 仍报 8s 所以"当静帧"触发不了;`reclip --input *.png` 实测正常且语义合法;"差异度闸报 `film1970 vs patina 0.94`"其实是**我自己一条 shell 引号写错、`grep` 读到了上一轮的旧日志**,干净重跑是 1.02 与改动前一致 —— 假警报的来源经常是量具而不是产品。留档未修的两条(预览 PNG 未走 O_EXCL、`rewind_preview` 目录无上限增长)进任务列表,不许悄悄忘掉。
50. **移一个控件,会暴露它新家里那条"从没人走过的分支"**:按用户要求把左栏收窄成日常层(只留预设 / 强度 / 系数 / 画幅·帧率·清晰度三组),年代轴与偏色移进高级参数。移完才发现 `@media (max-width:1200px)` 里是**无条件** `#rail-right { display:none }`(两处各写了一遍),而「高级参数」开关只切 `.pro-off` —— 于是窄窗口下年代轴**彻底拿不到**,等于顺手删了功能。这条一直存在,只是以前住在左栏所以没人碰。教训:① 控件换容器时,要量的是**新容器的可见性前提**(开关、断点、滚动),不是老容器的;② "同一件事两处各写一遍"在这里第三次发作(§8.1-36/39/43),两处 media query 内容完全相同就是信号。分层规则本身收进引擎 `describe` 的 `controls`(界面按清单渲染),这样"什么算日常"只有一个答案,要改就改一处;卡上 `~年代` 一并去掉时顺手修掉一个 i18n 泄漏 —— 「· 默认」原先写在 CSS `content:` 里,英文界面也显示中文,现在走词典。三条契约进 release_check(左栏不得含 `#era`/`#cast`、不得再写 `~${p.era}`、CSS `content:` 不得含中文)。
51. **修留档项长出的三条判据**。(a) **指纹命名的缓存必须原子写**:预览两张图的名字由参数指纹决定,并发同参数请求算出**同一个名字**,而旧实现让 ffmpeg 直接写最终名 → 后到的读者拿到半写的 PNG。把 `extract_frame` 退回非原子写作实测三轮:第 1、2 轮 16 张全好,**第 3 轮 10 张里 5 张解不开** —— 竞争是真的,但这条闸是**概率性**的,所以注释里写清轮次,不许拿"这次全绿"当"竞争不存在"。踩过的坑:临时名写成 `.name.png.part-<tag>`,ffmpeg 认不出封装器 → **所有**抽帧全挂;后缀必须留在末尾。(b) **"善意最小值"会吃掉用户的显式设置**:`REWIND_PREVIEW_MAX_MB` 第一版写成 `.unwrap_or(512).max(16)`,设 4 被悄悄抬成 16 MB,上限看似配了其实没生效 —— 是并发闸的新用例抓红的。正确形状:只有 0/非法才回落默认。(c) **断言查错量等于没断言**:极小图 DAR 那条最初写 `assert!(dw >= 16)`,而"放弃折算"分支恰好把宽度原样留着(16 也过)—— 塞一个 16×8 带 DAR 4:3 的假预设才暴露"闸是绿的但什么都没查"。改成查不变量本身:**凡声称有 DAR 的交付画幅,像素比例必须等于它**。同一条里还做了一次减法:极小图的退路**删掉了**,先算可达域(最窄交付画幅折出来 ≫16),走不到的分支不该写代码,该写成断言。

53. **边界是扫出来的不是想出来的,而"空转的断言"是本项目第三次犯**。#21 给 9 个高影响参数跑边界(`scripts/safe_max.py`),三件事只有扫过才知道:① `fps` 的清单范围是**倒挂**的(`min=60 / max=5`)—— `stepped()` 照抄降序档位表的首尾当范围;② `fps=1000` 不报错而是**"成功"** —— 8 秒素材变 8000 帧,84.08 s / 22.8 MB(正常 4.3 s / 7.2 MB),一个手滑贵 20 倍没人拦;③ `band_quantize.level=0` 把 `[Parsed_lutyuv_2] Error when evaluat…` 原样丢给用户。同时扫出六个**已经正确钳位**的参数(`unsharp.amount`/`fps.shutter`/`codec q`/`saturation`/`tape_ends.head` 等:越界值与边界值产出**字节相同**的成品)—— 这条"相同"就是钳位生效的证据,不用改。写闸时又踩了老坑:清单不变量我读的是 `p['bounds']['min']`,而字段在顶层,于是断言**永远读到空、永远绿**;是"注入 B(把 `stepped` 退回照抄首尾)本该报红却全绿"暴露的。补法与 §8.1-47 同一条:**断言必须自报覆盖面**(这里要求"至少读到 40 个带范围的参数"),覆盖面为 0 的绿就是没绿。判据成型:**边界值的验收看三件事 —— 拒绝是否说人话、合法极值是否仍出片、收紧是否误伤内置内容**(11 预设 + 11 个年代产物全部要能出计划)。

55. **"同一规则写两遍"会以两种形态复发:一处瞎掉,一处互相遮蔽**。第二轮同类扫查(两路只读审计 + 每条自己复现),落到实处的七条里,有两条是我当天早些时候为了修前一条而造的。
   ① **Web 版看不见失败**:`serve` 把子进程 stderr 接到 `/dev/null`、只转发 `progress`/`done`,而 CLI 的错误走 stderr —— 实测一次失败的任务,事件流里只有 `{"type":"batch","done":1}`,那一项永远等不到 item,进度遮罩停在那里,用户只能刷新页面。修法是失败同时走两条通道:引擎在 stdout 打 `{"type":"error"}`(`main::report_err`),serve 翻译成 `item{ok:false}`,同时把 stderr 收进缓冲作为 panic/被外部信号杀的兜底。**闸必须能区分两条通道**:第一版只断言"item 里有原因",注入"serve 不翻译 error 事件"照样绿(兜底把原因送到了);改成"原因必须来自 error 事件"之后才红。
   ② **取消与中间趟失败留下的鬼文件**:引擎被 kill 就没机会收尾,实测一次取消在用户「Rewind输出」留下 2 个隐藏 mp4 / 5 MB。解法是把运行标签随 `start` 事件报出去,父进程凭 `.tmp.<tag>.` 精确清理(并发另一手与用户文件绝不误伤,单元测试把三种"必须留下"钉住)。同一族的还有一处不需要 kill:第 N 趟失败时只删了当前趟的 `step_out`,上一趟的 `prev` 却在"成功之后"才删 —— 任何中间趟失败都留一个鬼文件(假 ffmpeg 放行前两次调用就能稳定复现)。
   ③ **静帧判据写在两处,错的那份在报告里**:`MediaInfo::is_image()` 与素材报告各写了一份 `duration<=0`。裸 H.264 流(`.264`)实测 ffprobe 报 duration=0 → 被当静帧:时序 stage 被剥、`-frames:v 1` 只出一帧、成品还是塞进 `.264` 文件名的 PNG。判据改成"没时长 **且** 容器是静态图片 muxer",报告与管线合并到同一个函数。顺带**证伪**了审计里更吓人的一条:`.ts` 没问题(ffprobe 给得出 6.046 s)。
   ④ **覆盖参数只校验名字不校验区间**,实测 `--override noise.alls=99999`、`resize.w=1` 一路放行并真出成品。而我为了修它踩到新坑:直接把清单 `min/max`(那是**界面档位** / 滑杆范围)当成硬限制,于是 `fps=80` 被当非法、`resize.w` 挡掉 8K 素材的「源」钉值 —— 两个概念挤在一个字段里的代价。最终拆开:`min/max` 仍是界面范围,新增 `hard_min/hard_max` 是引擎硬区间,数字取自 `ffgraph` 的常量,报错与清单共用同一个 `range_text`(所以不会再出现 "1–120" 与 "1-120" 两种写法),边界闸反过来断言"硬区间必须包住档位"。
   ⑤ **预览指纹只认预设 id**:「换一批」把种子 11 改成 12、id 不变,预览直接 `cached:true` 端出旧帧,等于"换了但没换"。指纹改为认**解析后的预设内容 + 素材字节数与 mtime**,并且格式版本从 `pf-geo2` 升到 `pf-geo3`(旧缓存必须整体作废,否则同名命中旧图现象照旧)。

   ② 三个 crate 相互独立,壳不能 `use` 引擎的常量表,所以码值只能**手抄**;手抄就要有对账 —— `shell_codes_exist_in_engine_table` 逐条查"常量存在 **且** 进了 `CODES` 数组"。写这条时自己踩了一个更隐蔽的坑:按 `']'` 切数组只切出 8 个字符(类型 `&[&str]` 里就带一个 `]`),断言会在"什么都没读到"的情况下继续跑 —— 那条 `body.len() > 40` 的守卫就是为这个存在的,它当场红了。
   ③ **"任何失败文本必须带码"的闸,第一版是恒真的**:判据 `contains("Err(")` 被 `Err::<(), _>("中文")` 绕过(注入测试照样绿)。改成扫"行内是否有含汉字的字符串字面量",当场又抓到三处漏网的(两处 `.ok_or("…")` 与一条日志)。教训:**判据要绑在内容上,不能绑在某个具体写法上**;而每条闸都必须做一次"注入必红"的证明才算数。
   ④ 豁免也要写理由:`.expect()`(程序性断言,走到就是 bug)与 `println!/eprintln!`(终端日志)到不了界面,所以不要求带码;`serve` 起不来的两句同理;`构建预览计划失败: {e}` 不动,因为它包的是**已经带码**的内层错误,再套一层等于把别人的码顶掉。
   ⑤ 新增两个码 `engine.output`(引擎/ffprobe 的输出读不出结构)与 `run.canceled`(取消不是失败),码表 18 → 20;`CODES` 下限跟着抬,缩水就红。取消这条同时补了桌面侧的老问题:壳只能返回一条字符串,界面从前把它当失败弹红条 —— 现在按稳定码认出取消。**验到的程度**:shell 侧文本由 `cancel_prevents_queue_items`/`cancel_mid_flight_skips_remaining` 两条断言钉住(等的是 `[run.canceled] 已取消` 整串);界面那条 `canceled || error.includes('[run.canceled]')` 分支需要真的桌面事件才能走,本机没有 GUI 依赖,与"壳手感测不了"同一类边界,不当已验证。
   ⑥ 已知边界留档:`AppSettings::save` 的三句 IO 失败仍未带码,它需要一个"配置写不出"的新码,而码表要求新码在引擎侧有真实调用点 —— 不为凑调用点改代码。

60. **"控件在界面上、值在引擎里没人吃"这一族,靠人眼是扫不出来的**(参数活性闸 + 一个从上线起就选不动的参数)。
   ① 起因是给 #12 做"每个旋钮都要真的改画面"的闸时,顺手把判据推广到**全部 75 个参数**:同一个上下文里 `--override stage.key=A` 与 `=B` 两份 `plan` 必须不同。结果第一条就撞出 `chroma_decimate.to` —— 4:1:1 / 4:2:0 / 4:2:2 **三个选项全部必然失败**:覆盖值解析不看清单 `kind`,只看"像不像数字",于是 `"411"` 变整数、serde 要字符串,报 `[preset.load] 覆盖后预设非法: invalid type: integer 411`。预设文件里写字符串一切正常,所以成品、画廊、回归闸全是绿的 —— 这类缺陷只有"从界面这条路走进引擎"才暴露。
   ② 判据要**绑在痕迹上,不绑在写法上**:`parse_scalar` 的旧形状是"先试 i64 再试 f64 再退回字符串",对 enum 就是错的。同类错误我在闸脚本上又犯了一次(第一版用 `contains("Err(")`,被 `Err::<(), _>("中文")` 绕过)。
   ③ **计划文本不许藏东西**。`tape_hiss` 的 `color/amplitude/mix_weight` 走 extra input + `filter_complex`,不在 `af` 列表里,计划里只剩 `+hiss` 一个标记 —— 改了参数计划一字不变,"拧了没反应"根本查不下去。现在把具体参数写进标记(`+hiss(anoisesrc=color=pink:amplitude=0.015:duration=8.5:weight=0.5)`)。`plan` 是这个项目唯一的结构出口,它不诚实,所有结构断言就只能覆盖它露出来的那部分。
   ④ **"条件生效"不等于"死控件",闸必须带开关上下文**:`unsharp.size` 只在 `amount > 0` 时成形,而 `amount` 是做旧系数 ≥6 手才拉起来的 —— 所以闸按多个上下文重试(带 `unsharp.amount=1.2`、`preset.aging=7`),`optional_enum` 则按"给值 / 不给值"配对。真扫不出痕迹的只能进 `EXEMPT` 且**必须写理由**;空豁免表才算这条闸在干活。
   ⑤ 红证明与成本:注入一个没人消费的 `crt_display.bogus_probe` → `FAIL=1`,还原 → `OK(75)`、`cmp` 一致;全表 156 次 plan 对比约 10 秒,所以敢进 CI。
   ⑥ 顺手补了 `conc_check.sh` 缺 `PASS` 计数器的问题:它只报 `FAIL=0`,于是"检查条数掉了"这件事从输出上看不出来 —— 闸的自述也要能证伪。

61. **结构对账之外还要一层像素对账:参数活性闸与"探针也是被测对象"**(像素活性闸上线)。
   ① `param_liveness` 只证明"值进了 `plan`"。计划里有痕迹 ≠ 画面会动 —— 滤镜参数可能被 ffmpeg 静默忽略、可能被上游的 0 值吃掉、也可能那个区间根本跑不通。所以补一层 `param_pixels`:每个视觉参数两个取值各出一帧小预览,**成品帧 md5 必须不同**。两层一起才叫"接上了"。
   ② 当天抓到两个:**探针太粗**(`codec_roundtrip.codec` 在 260px 下两帧一字不差,400px 才看得出压缩差异 —— 闸自己也要被量一次);**清单区间跑不通**(`unsharp.size` 发布 3–15 步长 1,而 ffmpeg 只吃 3–13 的奇数:偶数报 `Invalid even size`,14 报 `matrix size too big` —— 界面上等于一半刻度按下去就是一趟失败)。修法两层:清单给 `3–13 步长 2`(界面滑不出非法值),引擎把越界值贴到最近合法值(手写预设不该让渲染死掉)。
   ③ **闸的三种假绿各自踩过一次**:复用输出目录 → 上一对的 png 被当成这一对的结果,报出一个不存在的故障;把引擎必写的 `_src.png` 当成产物 → 所有尺寸"通过",于是"跑不出图"的判据形同虚设;`跑不出图 = 跳过` → 引擎对这个参数开始报错时闸反而是绿的。现在的规矩:每次尝试独立目录、只认带预设名的成品帧、跑不出图算失败、失败重试一次,再加 `--selftest`(同值两跑必须同帧、不同值必须不同帧 —— 判据既能判同也能判异)。
   ④ 写这个补丁时是**既有测试**抓到我改坏滤镜串(第一版 `format!` 参数顺序错位,把锐化强度填进了核尺寸的位置;`blow_tier_turns_on_sharpening_at_six_hands` 断言的是 `unsharp=5:5:1.2…` 的确切形状,当场红)。新测试测新性质、旧测试护旧形状,两者不可互相替代。
   ⑤ 边界要说实话:帧哈希看不见音频。13 个音频参数与 2 个纯音频形状进的是**成类豁免**,理由写成"本闸边界",并明确"逐参数听觉活性暂无闸、regression 只管健康度(单声道/无爆音)" —— 不许把它写成"已覆盖"。**这一层随后由 #62 补上**,豁免措辞也跟着改成"由 `param_audio` 看着"。

62. **"暂无闸"不是一条永久的豁免:音频活性闸**(补 #61 的盲区)。
   ① 像素闸的豁免清单当时是唯一写着"没有闸"的地方,而它盖住的恰好是最难用眼睛验证的一族:底噪、带限、抖晃、位深破碎 —— 帧哈希天生听不见。补法与像素层**同构**才算补齐:每个音频参数两个拉开的取值各跑一趟**真成品**,把成品里的音轨抽成 `f64le` 裸流比 md5,必须不同。清单里 8 个音频段的参数之外,还要带上 2 个"挂在视频段、却只改声音"的形状(`codec_roundtrip.audio_bitrate` / `video_only`)—— 按段名挑就漏了它们。
   ② `video_only=true` 那一边**根本没有音轨**。这类"一边有声、一边无声"是生效的证据而不是失败,但要写死在台架注释与判据里(`audio_hash` 用空串专门表示"无声轨"),否则下一读代码的人会把它当异常修掉。
   ③ 基线只有 **7/10** 个预设可用:`tape_hiss` 走的 `anoisesrc` 每次给自己换一段噪声,音轨复现不了 —— 拿它当基线就是把"噪声又随机一回"读成"参数起作用了"。所以先跑 `deterministic()` 预检(同参数两遍必须一字不差),不可复现的预设不进判据;一个都没有就 `SKIP`。这一趟里"同值→同轨"与 15 对"异值→异轨"两个方向都证到了,不必再单独立一条 `--selftest`。
   ④ 第一版报出 3 个**假故障**:`dvd2005` 那一趟的音轨是 **copy** 过去的(视频重压、声音原样搬),于是 `bitrate_roundtrip.bitrate` 这类参数怎么拧都"一字未变"。这和 #61 里"探针位置错了不是控件死了"是同一种错:**判据在错的位置上必然恒等**。修法是基线逐个试(先挑带这段的预设,再轮到其它可复现预设),试到最后一个仍不动才判红。
   ⑤ 一句自我提醒:当初写下"暂无闸"是诚实,停在"暂无闸"就是偷懒。豁免清单里每一条都该问一遍"这条是边界,还是只是还没做"。
   ⑥ 收尾时给三条活性闸各补一条**"清单为空即 FAIL"**:`describe` 的段名被改、或它报错却没抛时,零个判断照样打印成 `OK(0 对参数…)` —— 那是最假的绿。红证明的第一版**本身是空的**:判据写成"只要 `rc=1` 且输出里出现 `FAIL` 就算证明过",而锚点 `for sec in ("video", "audio")` 在 `param_liveness.py` 里有四处、`.replace(a, b, 1)` 只换第一次(落在 `structure()` 里),于是红了、红的却是另一条判据,新 guard 一次都没被碰到。改成**锚定完整一行 + 断言期望的那句文案出现**。**红证明的判据必须认"这一条红",不能认"任何红"**;注入点的锚还要唯一(与 §8.1-47、§8.1-60② 同族:量具先要能分辨它声称分辨的东西)。

63. **用户问"这个文件为什么在这儿",是一个 signal,不是闲话**(`vendor/` 里的 balloons.png → 一句假合规声明 + 一条上线阻塞)。
   ① 起因只是三个目录疑问里的一个:`vendor/ntsc-rs/benches/balloons.png` 是什么?查出来是 510 KB 的第三方测试照片,被上游 `include_bytes!` 进 criterion bench;我们只链接这个 crate 的库、**从不跑它**。于是它全部的存在感就是"随我们的 MIT 仓库分发一张来路不明的照片"。顺带把同一目录的声明一查,发现更硬的一条:`THIRD-PARTY-NOTICES.md` 写着内联目录"保留其 `LICENSE-*` 与版权头",而实测 `find vendor -iname "LICENSE*"` 为空、16 个 `.rs` **零版权头**。声明文件里每句话都会跟着安装包出去,**没被实测撑住的那句就是假话**。
   ② 动"看起来没人用"的目录之前,先证明它没人用:`grep -rn "^use image\|image::\|criterion" vendor/ntsc-rs/src` 只在 `benches/` 命中(库代码不碰),才删掉 bench + 配套 `[dev-dependencies]`(criterion、image)+ `[[bench]]` 段;`src/` 一字未改,并在 `Cargo.toml` 与声明里写明这是**本地改动**(内联第三方源码改了必须说改了哪里)。删完复测:core 77 项测试、`ntsc_check.sh` 21/21;`vendor/` 892 KB → 384 KB。
   ③ 补许可全文本机做不到,但"做不到"要量:GitHub raw 连接被重置、crates.io 与 static.crates.io 返回 **403**,对照组 `example.com` = 200 —— 结论是"这几个域名被拦",不是"没网"(§8.1-53 同一习惯:任何"做不了"都要指明哪一层拦的、并带一条必须失败的对照)。**不凭记忆重写 MIT/ISC 文本**(版权行要落上游作者与年份,写错比空着更糟);改为把补齐命令 + 两个互相矛盾的上游指向(vendored `Cargo.toml` 写 `valadaptive/ntsc-rs`,本文 §2 写 `ntsc-rs/ntsc-rs`)如实写进声明 §2.1,并让 `release_check` 有一条**当前就红**的闸盯着 —— 红着比"看起来已过"诚实。
   ④ 三条新闸(必须有许可全文 / 内联目录不许有素材 / 缺着必须在声明里承认)全部双向证明:注入 → 精确红,撤除 → 精确绿,`THIRD-PARTY-NOTICES.md` 还原后 `cmp` 逐字节一致。顺手清掉自己造的两件垃圾:49 MB 的 `vendor/ntsc-rs/target/`,和不在 ignore 里的 `vendor/ntsc-rs/Cargo.lock`(下一次 `git add -A` 会把它扫进仓库)—— `.gitignore` 补 `vendor/**/Cargo.lock`,闸 prune `target/`。
   ⑤ 同一批疑问的另外两条结论:`fixtures/` 看着像可删的临时件,实测被 regression、aging、ntsc_check、三条活性闸、`shell` 测试与 `release_check` 契约共 **17 处**引用(两个 lavfi 合成件,213 KB)—— **删不得**,README 改成写明引用面;`shell/` 不并进 `app/` —— app 只有 214 行 Rust,而 shell 的 925 行协议层 + 12 项测试的价值正在于**无 GUI 依赖也能编译测试**,并进 app 会把 tauri/webkit 拖进这条路径(本机无 webkit、Windows 无 MSVC 工作负载,CI 的 core+shell job 也不装 GUI 依赖),12 项测试当场变成测不了。三个 crate 不合并同理:壳不许 `use` 引擎的码表,才逼出了 `shell_codes_exist_in_engine_table` 这条跨 crate 对账(§8.1-60②)。

64. **第一次推送才是第一次真正的 provenance 审计**(`reference.png` 换源 + 公开/本地两条历史线)。
   ① `assets/reference/CREDITS.md` 早就写着"许可未确认,发布前必须解决",但这句话在仓库里躺了几天,谁也没被它拦住 —— 因为它不是闸,只是一句诚实的备注。**"待解决"写在文档里不等于被管住**;要管就得让某条检查在当前状态下是红的(`release_check` 现在有一条:声明里出现"未确认 / 发布前必须解决"就判红)。

   ③ 换源做法:用自有素材 `assets/sample/street-food.png`(1792×1024,本项目生成,MIT)裁一行得到 **1792×1023** —— 保住"奇数高度"这个 F1/F10 活体测试件性质,且不做任何放大(缩放会把要展示的细纹理抹平)。重烘 11 预设 × 四类资产实测 68 秒;`preset_gallery.sh --check` OK,`preset_variance.sh` 54 对全部可分辨,最小综合距离从 1.02 变到 **1.09**(阈值 1.0)—— 换锚点会整体挪动距离分布,这两道闸必须跟着重跑;余量仍薄,压线时先怀疑量具而不是先调阈值。
   ④ 两条历史线:**详细过程留在本地**(`main` + tag `pre-public-backup`),**公开侧一个干净初始提交**。用 plumbing 做(`write-tree` → `commit-tree` → `branch -f main-clean`),不碰 HEAD、不碰工作树,所以不受"提交推迟期禁用 restore/checkout"的约束;推送 `main-clean:main`。代价要说清:公开仓库看不到里程碑过程,过程记录改由 `CHANGELOG.md` 与本文件承担。校验用对象哈希:公开提交的 `ls-tree -r` 里不许出现旧帧 blob。
   ⑤ 署名:新提交用 GitHub 给的 noreply 地址(从 `api.github.com/users/<login>` 取到 id,拼 `<id>+<login>@users.noreply.github.com`),不改仓库 config,只按命令覆盖。旧 20 个提交仍是占位 `young@localhost`,它们只留在本地,公开侧那个初始提交是干净署名 —— 顺带说明为什么"占位身份"这类事最好在首次推送前处理。
   ⑥ 同一批推送前检查里量到的:`api.github.com` 通、`raw.githubusercontent.com` 连接被重置、`crates.io` 403 —— 所以 vendor 许可全文这件事本机补不了是**测出来的结论**,不是猜的;而 GitHub API 可达意味着推送之后能直接查 Actions 首跑状态,不必靠浏览器。

## 13. 参数面扩展与真实感补全(v1.4 定案 → M4)

> 触发:用户判"可调参数还是较少,帧率这类重要维度无法调整",要求横向深度调研如何更接近真实老片。
> 调研四路并行(代码参数面盘点 / 老片实测特征 / ffmpeg 可行性与成本 / ntsc-rs 未用表面),可行性已在本机 ffmpeg 4.4.2 与 `vendor/ntsc-rs` 源码上逐条验证过。

### 13.0 先摆结论(定案,不再讨论)

| # | 定案 | 依据(实测) |
|---|---|---|
| 1 | **参数少是架构问题,不是参数问题**:UI 只暴露 4 个控件(预设/年代轴/强度/输出目录),而 JSON 里已有 22 种 stage、40+ 参数无人可调 → 建"引擎发布参数清单(manifest)+ UI 按清单渲染"机制,一次解决"以后每加参数都要改 UI"的死循环 | `app/ui/index.html` 全部控件清点;`start_jobs` 载荷只有 4 个字段 |
| 2 | **帧率必须成为一级控件并修好管线**:`fps` stage 早已存在,但 ①UI 无控件 ②`era.rs:166` 只在 `p.fps<29.5` 时才生成 ③**PixelPath 直接忽略它**(`pixel.rs:39` 取源帧率) ④`InterlaceComb.refps` 是 fps 的第二份拷贝,会漂移 | 四处代码行号见 §13.2 |
| 3 | **最大真实感缺口是几何不是噪声**:全仓零处 `setsar/setdar/aspect`,输出恒为方形像素 16:9;真老片是 4:3 + 非方像素(NTSC 10:11、PAL 12:11、DV 59:54、DVR/128×96 是 1:1)+ 每轴 5% overscan 裁切 | 实测规格表 §13.3 |
| 4 | **PAL/NTSC 区域轴完全缺失**:年代轴是纯 NTSC 视角(ntsc-rs 只模拟 NTSC M),而中国素材是 PAL-D/K(25fps/50 场、4.43MHz、相位翻转把偏色变成**去饱和**、6.5MHz 伴音、1973 前才是黑白) | §13.4 |
| 5 | **损坏要从"常数"改成"事件"**:现有 noise/tape_ends 是均匀/固定窗口;真磁带的故障是**触发式**的(dropout 竖条 2–3 行长、脏磁头每转一周一条并 1–3Hz 下滚、跟踪旋钮每 5–30s 被人拧一次、恢复斜坡 0.1–0.5s) | §13.5 |
| 6 | **供电哼声 0 覆盖**:50Hz(PAL)/60Hz(NTSC)工频梳 + 100/120Hz 画面亮度纹;NTSC 下 60 vs 59.94 的拍频会让暗条 16.7 秒滚一周 | §13.5 |
| 7 | **ntsc-rs 的 62 个信号级旋钮一个没用**,且上游自带 JSON 桥:`SettingsList::<NtscEffect>::new().from_json(flat_json)` 直接返回可用效果体;`all_descriptors()` 还免费给出每项的区间/标签 → **专家面板的 NTSC 分组由上游描述符自动生成,我们不硬编码区间** | `src/settings/settings.rs:824`、`standard.rs:421-1142` |
| 8 | **全范围/限幅范围是廉价巨大 tell**:`scale=in_range/out_range` 在 4.4 可用,VCD/DVR rip 常见 0–255 全范围("黑场发灰"),我们现在恒为 tv 范围 | 本机 `ffmpeg -h filter=scale` |
| 9 | 低帧率要"旧"不要"卡":条件是**运动模糊随帧距放大**(`fps=12.5:round=down` 纯丢帧不重复帧 + `tmix` 按快门角给模糊 + 场序),naive `fps` 默认 `round=near` 会重复帧 → 现代掉帧感 | 本机确认 `round` 选项存在 |
| 10 | 真 3GP/监控音轨可得:本机 4.4 有 `libopencore_amrnb`(AMR-NB 12.2k)、`adpcm_ima_*`、`mp2` → 3GP 与 DVR 的音频身份可以真编码,不再只靠带限近似 | `ffmpeg -encoders` 实测 |

**明确不做**:SECAM(法国/苏联素材,需求薄且要再引一条制式链)、GPU/GLSL 着色器(违背 CPU-only 三端同构)、OFX(`oflopen` 不在 4.4)、逆 telecine(`fieldmatch/decimate`,我们的输入是渐进数字素材,不需要逆)、暂停帧噪声(继续 parked)。

### 13.1 参数暴露架构(schema v1.1,全部新字段 `#[serde(default)]` 向后兼容)

**引擎侧**
- 新增 CLI `rewind-core describe` → 输出**参数清单**:每个 stage 的 `{stage, group, label, params:[{key, kind, min, max, unit, default, scaled_by_intensity}]}`,并附 `ntsc:[…]`(来自 `all_descriptors()`,不手抄)与 `region:[ntsc,pal]`。
- `app_info` 响应带上这份清单 → 桌面壳与 Web 版**共用同一套渲染代码**(遵守"同类控件只许一个实现")。
- **覆盖层 `overrides`**:预设 JSON 里新增 `{ "overrides": { "<stage>": { "<param>": value } } }` + 一份 `pinned` 名单;年代轴重生时保留 pinned 参数(现在 `era_{year}.json` 是无条件覆写,手改会被吞)。

**界面侧(三层,默认不占位)**
- L1 主路径(已有):年代轴 + 强度乘子 + 预设。
- L2 **四个物理量一级控件**(新增,常驻):①画幅与制式(4:3/16:9 + PAL/NTSC + overscan)②**帧率与节奏**(24/25/29.97/15/12.5/10 + 丢帧 or 模糊 or 场序)③清晰度/带宽(分辨率比例 + 全/限范围)④代际(翻录次数,已有一半)。
- L3 专家面板(折叠):按 group 分节——信号级(NTSC 62 旋钮,清单来自上游)/几何/色度/暂态损坏/色彩/音频。区间由 manifest 决定,越界引擎再钳一次并在状态栏回报。
- L4 直接改 JSON(`docs/guide/预设格式.md` 已覆盖,补 overrides 一节)。

### 13.2 帧率与节奏(P0)

新参数(`Fps` stage 扩展):`fps`(浮点,允许 29.97/23.976)、`round:"down"|"near"`(默认 down = 纯丢帧)、`shutter:0..1`(→ `tmix=frames=2:weights="1 1"` 强度)、`cadence:"none"|"telecine32"|"pal_speedup"|"interlace_field"`(→ `telecine`/`setpts+atempo`/`tinterlace`)。
四必改项:
1. `pixel.rs`:把段生效帧率塞进解码链(`-vf scale=W:H,fps=X,format=rgb24`)并按该帧率算总帧数与输出 `-r`,否则像素预设的 fps 参数永远是装饰。
2. `era.rs:166` 取消 `<29.5` 条件,始终写 `fps` stage;`InterlaceComb.refps` 改为从同一来源派生(单源,删第二份拷贝)。
3. 输出容器帧率元数据 `-r`(现在 FastPath 完全没有 `-r`,靠滤镜链隐式)。
4. 锚点值按真实规格校准:8mm 16/18、电影 24、NTSC 29.97i、PAL 25i、VCD 25、DVR 6.25/12.5、3GP 10–15、FLV 15。
验收口径:`ffprobe` 读 `r_frame_rate/avg_frame_rate` + `nb_frames` 与时长比值;`shutter>0` 时相邻帧均差应显著上升(复用现有 persistence 的相邻帧差度量法)。

### 13.3 画幅/几何/量化范围(P0)

`Resize` stage 扩:`dar:"4:3"|"13:9"|"16:9"|null`、`par:"10:11"|"12:11"|"59:54"|"1:1"|null`、`overscan:0.88..1.0`(先裁后放,顺序很关键)、`range:"tv"|"pc"`、`flags:"area"|"bilinear"|"neighbor"`。
- 实现:`crop=trunc(iw*O/2)*2:trunc(ih*O/2)*2`(保偶数给 4:2:0)→ `scale=W:H:flags=...,in_range=...,out_range=...` → `setsar=N/D`(或 `setdar`)。
- **带宽用"降-升采样"而不是模糊**(4.4 无 `freqpass`):`scale=iw/k:ih/k:flags=area,scale=W:H:flags=bilinear`——比 gblur 便宜一个量级且是真实的模拟带宽限制;`AsymLowpass` 保留为附加软化。
- 7 个内置预设 + 8 个年代锚点全部按 §13.3 的规格表重定标(这是**观感改动最大**的一批,定标要出对照样片)。
验收口径:`ffprobe` 的 `sample_aspect_ratio`/`display_aspect_ratio`/`color_range` 三项断言 + 视觉对照表 `.work/samples/sheet_geometry.png`。

### 13.4 区域制式 PAL/NTSC(P1)

预设新增顶层字段 `region:"ntsc"|"pal"`(默认按年代轴与素材推定)。它驱动:场率(29.97i/50i)、工频 hum(60/50Hz)、色度错误形态(NTSC ±10–20° 偏色 vs PAL ±10% 去饱和)、PAL 垂直色度减半(`chroma_vert_blend`/1 行延迟线)、PAL 无 pulldown、24→25 的 +4% 速度联动(音高同步升 0.7 半音)、1973 年前中国素材黑白门控。
ntsc-rs 只在 NTSC 分支用;PAL 走 ffmpeg 近似链 + PAL 专属参数(去饱和、垂直色度合并、50Hz)。
验收:同一素材两制式对照 `.work/samples/sheet_region.png`,并断言 PAL 输出的色度饱和度均值显著低于 NTSC 分支。

### 13.5 事件化暂态损坏(P1)

| stage | 参数 | 路线(4.4 实测可用) |
|---|---|---|
| `dropout` | rate(次/秒)、width_px、brightness、seed | 多条 `drawbox=x=…:y=0:w=…:h=ih:t=fill:enable='lt(mod(t+φ,P),W)'`(脏磁头=按转周期重复且 φ 随 t 漂移);位置/周期由我们的 Xorshift 生成 → **可复现,吃"换一批"** |
| `weave` | amp_v_line、amp_h_px、hz、seed | `crop=iw-2a:ih-2a:a+a*random():…,pad=…`(crop 逐帧重求值,已确认) |
| `roll` | px_per_s、gap | `pad=iw:ih*2:0:0,crop=iw:ih:0:'mod(k*t,ih)'`(真环绕,代价:2× 带宽) |
| `tracking` | band_pct、shear_px、每 5–30s 触发 | 取代现 `tape_ends` 的固定首尾窗口,事件序列 seed 生成 |
| `hum` | hz(50/60)、level、harmonics | `aevalsrc='a*sin(2πft)+b*sin(2π3f t)+…'` + `amix`(注意 amix 归一化,需补偿) |
| `mains_flicker` | hz(100/120)、depth% | 像素层逐帧亮度纹(便宜);NTSC 下加 16.7s 滚动暗条 |
| `color_hunt` | hue_amp_deg、hue_period_s、bright_amp_db、seed | `sendcmd` 时间脚本驱动 `hue=h`/`eq=brightness`(脚本由我们的 seed 生成 → 确定性) |
| `chroma_lag` | frames(1–2) | Rust 逐帧:上一帧色度与当帧混合(ntsc-rs 的 chroma delay 是**空域**的,时域滞后必须我们做) |

验收:单位时间事件计数(逐帧亮度方差峰检测)+ `sheet_dropout.png` 对照;回归闸逐轴加断言。

### 13.6 色彩与色度(P2)

`illegal_chroma`(BT.601 往返改**环绕**而非软削,模拟非法色相角:青色头发/绿色天空的洗感)、`monochrome`(`gray`/`p43_green` 夜视单色——**注意:真 intensifier 监控是单色绿,IR 补彩的是品红,绿+彩是错的**)、`fade`(`eastman_magenta` 品红衰减:`curves`/`colorlevels` 或 `lut1d`)、`halation`(高光泛晕:`split`→阈值曲线→`scale=iw/4`→`gblur`→`scale`回→`blend=screen`,**降采样先于模糊**是成本杠杆)。

### 13.7 音频末端链(P2)

`speaker`(电视内置喇叭 300Hz–5kHz + 1–2kHz 峰:`highpass/lowpass/equalizer`)、`broadcast_agc`(`acompressor`/`dynaudnorm` 的抽风感,1980s–2000s 电视台峰值 −9…−6 dBFS)、`AudioCodec` 扩 `codec` 字段(真 `mp2` 224k=VCD、`adpcm_ima`=DVR 32k、`libopencore_amrnb` 12.2k=3GP、`aac`)。VCD 的中国特写:双 112k 音轨(伴唱/原唱)可作为 easter egg,不进 MVP。

### 13.8 ntsc-rs 全量接入(P0,route A)

`NtscVhs` stage 新增 `settings:{…}`(flat JSON,`version:1`),`pixel.rs` 改走 `SettingsList::<NtscEffect>::new().from_json(merged)`。
**三个必须防的坑**:①`from_json` 的基线是 `legacy_value()` 而非 `default()`(漏写 `luma_noise` 会被关掉、`filter_type` 变 ConstantK)→ 先用 `to_json_string(&NtscEffect::default())` 生成完整模板再合并用户覆盖;②`FbmNoiseSettings` 无 `Default`、`NtscEffect` 是 `#[non_exhaustive]`;③未知 key 静默忽略 → 我们自己在 manifest 侧校验 key 名并报错,别让用户写错参数后无声无息。
可直接拿到的用户语义旋钮:`vhs_tape_speed`(SP/LP/EP → luma 截止 2.4/1.9/1.4MHz = **"带速"是用户能理解的"更破"的开关`)、`tracking_noise_*`、`head_switching_*`、`snow`、`chroma_delay_horizontal/vertical`、`luma_smear`、`vhs_sharpen`、`vhs_edge_wave`、`chroma_demodulation`。
顺带性能项:`apply_effect_to_buffer` 每帧新建 `YiqOwned`(1080p ≈ 每帧 16MB 分配),改 `YiqView` 复用缓冲可省掉这块;先测收益再决定是否改(风险:借用复杂)。
