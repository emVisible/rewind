## 二、决策（我替你定的，附理由与改动点）


### D1 预设分三层：内置 / 我的 / 派生 —— 派生品不再进画廊

**问题**：F1 + F2。年代轴和"换一批"把临时产物写进用户预设目录，既污染预设列表，又会永久顶替内置预设。

**决定**：
- 预设带 `kind`：`builtin`（`presets/`）/ `user`（用户目录里用户主动保存的）/ `derived`（年代轴、换一批生成）。
- **画廊只列 `builtin` + `user`**；派生预设显示为画布上方一枚 chip：`派生自：年代轴 ~1996 · 存为预设`，点"存为预设"才升格为 `user`（弹一个命名输入，默认 `我的 1996`）。
- 派生文件改写 `<user>/derived/`（画廊不扫这个子目录），**并且不再每次滑年代轴都落盘**：年代轴改走 `--era <year>` 内联生成（引擎 `era` 命令本来就支持不写盘直接输出 JSON），只有"存为预设"和"换一批"才产生文件。
- 换一批保留写盘（要能重载恢复），但落 `derived/`，id 记进 settings，**不再覆盖内置同名文件**。

**改动点**：`core/src/era.rs:291`（name/id 不动）、`core/src/main.rs`（`era` 支持 `--stdout-only`）、`core/src/serve.rs:462-491`（use_era 不写盘 / reroll 落 derived）、`shell/src/lib.rs:226-239,378-385`（同上）、`app.js:581-603`（chip 渲染 + 防抖只算不写）。

**验收**：滑遍 1965→2026 后 `ls ~/.local/share/Rewind/presets/` **不新增文件**；画廊瓦片数 == 内置数 + 用户保存数；回归闸加一条"年代轴操作后用户预设目录不变"。

### D2 列表与画廊资产扫描只有一份实现，桌面壳补上

**问题**：F3 —— 合并/去重/排序逻辑在 shell 与 serve 各写了一份，gallery 扫描只有 Web 侧有，导致桌面版根本没对比图，且两份必然漂移。

**决定**：引擎出权威数据 —— `rewind-core catalog`（新子命令）返回 `[{id,name,era,kind,params,gallery:{tile,full,hero,motion}}]`，按 `ui/gallery/` 实际存在的文件填 `gallery` 字段；`serve.rs` 与 `shell/src/lib.rs` 都改成消费它（删掉两份本地实现）。桌面 `app_info` 带上同一份 catalog。

**验收**：`grep -c 'sort_by_key' shell/src/lib.rs core/src/serve.rs` 里只剩一处；桌面壳启动后画廊瓦片有图（这条**只能在 Windows 侧 GUI 冒烟时验**，本机无 GUI 依赖，见 §四 R1）。

### D3 默认预设 = 电子包浆 `patina`

**问题**：用户要的"初始预设"。研究结论：**包浆是减法**（重采样糊 + 块效应 + 色度抽稀 + 灰雾抬黑 + 轻色偏 + 断层），deep fried 才是加法（饱和/对比拉爆 + 锐化过冲）——默认档不开加法。

**决定**（预设 A"群聊三手"，实测静帧 0.66 s / 10 s 720p 2.84 s，够快）：

| 顺序 | stage | 参数 | 为什么 |
|---|---|---|---|
| 1 | `resize` | `w=1080 h=608 flags=area` | 平台首刀按长边重采样；`area` 是面积平均，无振铃，最像真实缩放（`lanczos` 会把丢掉的高频"造回来"，默认档禁用） |
| 2 | `codec_roundtrip` | `codec=mjpeg q=10 container=mp4 audio_bitrate=56k` | q10 ≈ libjpeg 75-80，"转发一次"的量化强度 |
| 3 | `resize` | `w=750 h=422 flags=area` | 累计 3.4× 落在甜点：实测 1/2 轻、**1/3 明显**、1/4 文字成糊、1/5 不可读 |
| 4 | `codec_roundtrip` | `mjpeg q=13` | 第二刀，块效应叠加但不完全塌 |
| 5 | `chroma_decimate` | `to=420` | 文字彩边（平台 JPEG 默认 4:2:0） |
| 6 | `band_quantize`（**新增 stage**） | `level=20 dither=0` | 8bit 色阶被砍出来的断层；ffmpeg 4.4.2 **没有** `posterize`/`banddither`，实测要用 `lutyuv=y=(trunc(val/L)*L+L/3)`，L=16~24 轻、32 重，2560×1439 单趟 285–412 ms |
| 7 | `resize` | `mode=source_canvas flags=bicubic` | 拉回原画幅（交付尺寸不变，用户不觉得"被缩小"） |
| 8 | `color` | `saturation=0.95 contrast=0.97 brightness=0.02` | **灰雾必须显式做**：实测纯黑过 4 代 mjpeg 后 YAVG 仍是 0，压缩不会自己抬黑 |
| 9 | `noise` | `alls=5 allf=u`（图片）/ `t+u`（视频） | 轻微颗粒，避免大平面死板 |

**同时新增第 2 个 stage**：`unsharp`（`luma_msize_x/y=5 luma_amount=…`，默认 0 关闭，重口档 1.2~2.5）——为了 D4 的"抽象高糊"与未来 deep-fried 档，不做进默认包浆。

**默认选中**：`state.preset` 初始为 `patina`；`presets/` 排序里给它 `era: 2016`（包浆不属于某个年代，属于移动互联中期），画廊位置靠首（`rank()` 给 builtin 里 `default=true` 一个置顶位）。

**验收**：`rewind-core run --preset presets/patina.json --input reference.png` rc=0、成品 2560×1438、体积与耗时进回归（阈值：静帧 < 1.2 s）。

### D4 预设集 7 → 12，每个都要"一眼能认"

**决定**新增 5 个（按用户高频需求排；`直播连麦切片`、`网课录屏`、`枪版 CAM` 留第二批）：

| id | 名称 | 一眼特征（签名 stage） | 用户为什么要 |
|---|---|---|---|
| `patina` | 电子包浆（默认） | 见 D3 | 表情包/截图传播的通用"糊" |
| `patina10` | 十手包浆 | A 骨架 + 两刀到 540、`chroma_decimate 411`、插一趟 `mpeg4 q=24`、`asymmetric_lowpass 1.2/6.0`、`brightness=0.035` | 梗图"传了十手"的夸张版，视频 4.46 s |
| `blurhigh` | 抽象高糊 | `640×360 area` → `libx264 220k` → `480×270` → `mpeg4 q=20` → 拉回 + `lowpass 1.5/8.0` | "高糊名场面"是弹幕/鬼畜固定语法，视频 2.76 s |
| `rmvb2006` | 字幕组 RMVB | `512×384` 4:3 + 低码率 H.264 + `overlay_timestamp` 关闭 + 硬字幕条 + 色板断层 | 鬼畜素材主体就是 VeryCD/迅雷时代的低清剧与 MV |
| `screenbat` | 屏摄翻拍 | 摩尔纹（`interlace_comb` 变体或栅格干涉）+ 桶形/梯形 + 高光反光 + 高感噪点 | "手机拍电视/拍投影"是包浆图的实物来源 |

**并且**：现有 7 个的**视觉差异**要按 F4/F9 修（见 D5），不是重做参数——参数差异已有数据支撑，弱对只有 ntscrs/static 一组（对照组，保留，但在名字上写清"信号级 / 静态近似基线"，已经写了）。

**验收（新闸）**：`scripts/preset_gallery.sh --check` 之外加 **`scripts/preset_variance.sh`**：读 `catalog`，断言（a）任意两预设的 stage 集合不完全相同；（b）任意两预设的 `_full.png` 缩略在 LAB 空间的均值距离 > 阈值（防"看着一样"）；（c）`ntscrs/static` 这类有意对照对在白名单里。这条闸把 F9 从"我量过一次"变成"每次 CI 都量"。

### D5 卡片用整帧缩略，hover 弹大图 1:1 分割

**问题**：F4 + F5 —— 118×66 px 显示 1:1 取块的 480×270，等于把预设差异压没了；而 `_full.png` 白躺着没人用。

**决定**：
- **卡片**改用 `_full.png`（整帧缩略）→ 看得出纳不纳、构图、色偏，小尺寸下反而更认得出差异。
- **hover 300 ms** 弹 popover（约 720×405，跟随卡片右侧、贴边翻转）：里面是**新增资产 `<id>_hero.webp`**（1280×720 的 1:1 中心分割，左原右旧，中间 amber 分隔线，WebP q80 预计 150–250 KB）+ 名称 + 一句签名特征 + 3 个最能代表它的参数读数。
- 卡片内自动播放的 webm **取消**（改成 popover 里的"动图"页签，点击才载 webm）——现在 4:3 的 webm 被 `aspect-ratio:16/9;object-fit:cover` 裁掉了（`style.css:91`，实测 cctv2000 是 480×360、vhs1990_static 480×320），既费流量又裁画面。
- 键盘可达：卡片 focus 等同 hover（popover 可 Tab 进入），`Esc` 关。

**改动点**：`app.js:139-189`（renderGallery/attachMotion → 换 popover）、`scripts/preset_gallery.sh`（加 `_hero.webp` 烘培 + `--check` 断言）、`style.css:75-94`。

**验收**：`preset_gallery.sh --check` 对 12 预设 × 4 类资产存在；popover 打开时 `getComputedStyle(popover).display !== 'none'` 且 `img.naturalWidth > 0`（用 M5a 之后的 computed-style 口径，不再用 `.hidden` 属性）。

### D6 参数行改两行制，标签必须完整可见

**问题**：F6。

**决定**：
- `.knob` 从 3 轨改**两行**：第一行 `label`（完整，12px，不许 ellipsis）+ 右端读数（`font-variant-numeric: tabular-nums`，右对齐，固定 92 px）；第二行滑杆满宽 + 可选"源"芯片右浮。
- 读数格式化 `fmtVal()`：最多 4 位小数并去尾零（`0.0029999…` → `0.003`），单位照旧；`跟随预设(0.003)` 完整可见。
- 右栏 `--rail-r: 292 → 320 px`；左栏不动。分组标题（`.kgroup-head`）与 `<summary>` 左边界、行左边界统一到同一个 padding（现在基础区 padding 8/10、高级区 6/10 不一致），并给 `index.html:98` 的 `.pro-groups` 补上真实样式（现在是死类名）。
- 静态闸：`release_check.sh` 加一条 —— `.knob > span` 规则里**不许**出现 `text-overflow: ellipsis`（防止以后又有人用截断糊事）。

**验收**：浏览器实测 59 个参数标签全部完整可见（遍历 `document.querySelectorAll('.knob > span')`，逐个 `scrollWidth <= clientWidth`），读数同理；这条**可以**在无头环境用 `evaluate_script` 量（M5 已验证过这套口径可用）。

### D9 傻瓜参数：**做旧系数 = 几手**（1–8 档，一次算好，不用重复操作）

**问题**：用户想要"把系数调高就直接做成电子包浆爆炸"，而不是手动反复点"再翻录"。现有 `intensity`（强度）只放大**单次**的幅度类参数，它回答的是"这一手有多重"；用户要的是"**几手**"——那是代际累积，是**趟数**，两者正交且都必须留。

**决定**：

1. **语义钉死**：`做旧系数 N`＝这张图/这段素材被"下载→重采样→再压缩→上传"**往返 N 次**。N=1 就是"过了一次平台"，N=2 是默认（群聊三手），N=6~8 是"爆炸档"。UI 刻度直接标手数：**1 手 / 2 手 / 3 手 / 5 手 / 8 手（爆炸）**，读数写 `3 手 · 约 4.2 s`。

2. **上限 8，且必须诚实**：研究实测**同尺寸同 q 反复往返会收敛**（8 代后 72950 B ≈ 单代 72956 B）。所以（a）滑块最大 8；（b）每一手**必须同时改尺寸**才不收敛——阶梯就是为此存在，不是装饰；（c）到 8 时 UI 明说"再高基本无变化，要更脏请调强度"。

3. **代际阶梯**（每个预设自带一套，缺省用通用阶梯）：
   - 尺寸：第 g 手长边乘 `0.72^g`（g=1→0.72，2→0.52，3→0.37…），落在实测甜点带（1/3.4 明显、1/4 文字成糊、1/5 不可读），**向下取偶**（`even_dim`，M6 已落）。
   - 量化：mjpeg `q = q0 + 1.5·(g−1)`（q0 由预设给，默认 10）；q 高端会饱和（实测 q20→31 体积只从 79 KB→66 KB），所以**高手数主要靠尺寸和色度推进，不靠 q**。
   - 色度：g≥2 才 `chroma_decimate 420`，g≥4 才 `411`（平台默认 4:2:0，4:1:1 是"贴吧绿"那一支）。
   - 断层：`band_quantize level` 从 24 逐手降到 12（越大越轻）。
   - 灰雾：`brightness += 0.012·(g−1)`、`contrast −= 0.01·(g−1)`（**压缩不会自己抬黑**，实测纯黑过 4 代 mjpeg YAVG 恒 0，必须显式累积）。
   - 色偏：`green_mid/blue_mid` 逐手微推（g≥3 起可见）。
   - 颗粒：`alls += 2·(g−1)`，上限 12。
   - **爆炸分量（g≥6 才开）**：`unsharp luma_amount 1.2→2.5` + `saturation 1.05→1.35`。这是刻意的相变——**包浆是减法，deep fried 是加法**，滑块后半段就是给用户"炸"的，前半段不许出现锐化过冲。
   - 最后一趟**恒拉回源画幅**（交付尺寸与 N 无关，用户不会因为调系数而改变导出分辨率）。

4. **哪些 stage 参与复手**：规则一句话——**几何与时间做一次，损耗做 N 次**。参与累积：`resize` / `codec_roundtrip` / `bitrate_roundtrip` / `chroma_decimate` / `matrix_roundtrip` / `band_quantize` / `unsharp` / `noise` / `color` / `color_fade`；只做一次：`fps` / `cadence` / `interlace_comb` / `tape_ends` / `crt_display` / `film_damage` / `overlay_timestamp` / `rec_badge` / `watermark` / 全部音频 stage（音频另设 `audio_gens = min(N, 3)`，因为底噪累积三手就满）。预设可用 `aging.core: [...]` 显式覆盖这个集合。

5. **与"再翻录"的分工**（避免两个入口打架）：`做旧系数` 是**一次算好**（单个 plan、确定性、无中间文件、可预览）；`再翻录`（reclip）保留为**物理复手**——真的把成品再喂回管线，唯一能复现"在已压缩素材上继续压"的蚊噪/块错位。UI 上 reclip 收进高级区，tooltip 写"物理再过一遍手；想快速变旧请用做旧系数"。

6. **成本与反馈**：每加一手 ≈ 多一趟编解码，视频耗时近线性（`patina` 2 手 10 s 720p 实测 2.84 s → 8 手预估 9–11 s，**P1 实测后回填真值**）。所以：滑块右侧实时显示"约 X s"，N≥5 出现 ⚠，预览仍走代理（#23）不受 N 影响太大。

7. **清单与三态**：`做旧系数` 进 `describe` 的一级控件（`group: "aging"`，`stepped`，1–8 整数，`scaled_by_intensity: false`），并支持钉住——它不是预设内部参数，而是 plan 修饰符，与 `intensity` 同级，走 `--aging N` CLI（`--aging 0` 表示"用预设自带的手数"）。

**验收（新闸 `scripts/aging_check.sh`，可机检、不需要人眼）**：
- **单调**：N=1..8 对同一源，成品与源的 `SSIM`（ffmpeg `ssim`）严格下降，且每档差值 > 0.002（防"调了没反应"，也防收敛后假装有效）。
- **块效应上升**：用 `blockdetect`/自算 8×8 边界梯度比，随 N 单调不降。
- **交付画幅恒定**：8 档成品尺寸完全相同且为偶数。
- **相变存在**：N=6 的拉普拉斯方差 > N=5（爆炸档的锐化分量必须真的生效），且 N=5 的 `unsharp` 不出现于滤镜串（前半段不许炸）。
- **确定性**：同 seed 同 N 跑两次，成品字节相同。
- **成本上限**：10 s 720p 在 N=8 时 < 20 s（超了就把上限降到 6 并改文档，不硬扛）。
- 图片模式全预设 × N∈{1,4,8} 不报错（静帧剥时序 stage 的既有规则要兼容复手）。

## 四、风险与未证实项

- **R1 桌面壳从未真机冒烟**（任务 #8 仍开着）：`app_info` 缺 gallery（F3）这类问题只在桌面版暴露，本机没有 GUI 依赖编译不了。D2 修的是数据源，桌面侧验证要等 Windows 构建。
- **R2 平台压缩参数是二手口径**（F12）：包浆预设的"1080 长边 / quality 70%"来自 2017–2026 的第三方文章，无官方文档。**动作**：做一次真机转发实测（原图 → 微信/QQ/微博各转一手，量尺寸与 DCT 质量），再回来定标 `patina` 的两刀尺寸与 q 值。在此之前 `patina` 的取值算"看着对"，不算"标定了"。
- **R3 同尺寸同 q 反复往返会收敛**（研究实测：8 代后字节数 ≈ 单代）→ "再翻录一次"必须**同时改尺寸**才有效果，否则用户点三下"再翻录"看到零变化。**未进实现**:`reclip` 目前仍是同尺寸 mpeg4 往返,下一步要么让它带阶梯,要么在界面上把"再翻录"指向做旧系数。
- **R4 新 stage 的边界**（已按预期落地）：`lutyuv` 表达式本身不含逗号,但仍按 §8.1-24② 的规矩单引号包裹;`unsharp` amount≤0 时**不插滤镜**,并由单测 `aging_ladder_adds_hands_and_restores_canvas` 断言"5 手不含 unsharp"。
- **R5 资产体积**（已实测）：12 预设 × 四类资产共 **8.5 MB**,其中 hero 37–86 KB/张(远低于 250 KB 预算);`release_check.sh` 的"无 >4 MB 文件"仍 32 项全绿。安装包 ≤80 MB 要等 M3 真打包复量。
